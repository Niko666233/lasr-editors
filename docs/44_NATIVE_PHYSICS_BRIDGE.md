## 0. 一句话结论

原版的轮胎/悬挂**不是**在 Java 里算的，也不是纯原生自算的，而是一条**四段接力**：

```
Java 每帧把「弹簧力 / 阻尼 / 自由长 / 上下限 / 胎簧刚度 / 胎半径 / 簧下质量」
        ↓ WheelRef 本机方法（18 个 setter，带合法性钳位）
原生 轮对象(WheelRef, 步长 0x1528) 与它的子结构(+0x24)
        ↓ ★ 车辆逐帧虚拟方法 0x469FE0（64 槽虚表 0x6EB500 的第 #39 槽）
           ① 逐轮悬挂解算（循环头 0x46AEE0）
           ② call 0x464F80 接触几何 + 用 0x4B9D50/0x4B9DF0 取位姿、
              写 12 dword = R[12]、call 0x4BBA40 提交刚体
           ③ 遍历 [车+0x1508] 链表 → call 0x45B010（局部力→世界系，逐项施加）
           ④ call 0x4A4860 关节件/部件安装解算（→ 0x4326D0）
```

★ 车辆物理是**一个巨型虚拟方法**（0x469FE0，>7 KB，一路内联），**不是**一串自由函数；
入口是 64 槽虚表 `0x6EB500` 的**虚调用** —— 这就是为什么它和 0x47CA90 都「没有 E8 调用者」。

★★ **更正（本轮推翻上一版结论）**：`0x4326D0` 创建的对象**不是**「每轮质点力累加器」。
它的 vtable（`0x6EF750`）紧跟的字符串是 **`uninstall error: jointed part!`**，
且它由部件安装/关节解算器 `0x4A4860` 调用 ⇒ 它是**车用部件的关节/附着件**（wing/rollbar/rod/link 一类），
`+0x18`=锚点、`+0x24`=半径、`+0x28`=第二锚点。上一版把它读成力的施加点是**错的**。

⇒ 「力→刚体」的**机制**已确证为引擎的 **`Spring` + `PhysicsRef`** 两体弹簧 API（见 §8），
而**逐帧施加点**是 `0x45B010`（从 `[车+0x1508]` 链表逐项调用）。

★★★ **本条已完全闭合（见 §9）**：力的出口 = `0x4B9FF0(体,&F,&T)` → 引擎 `0x67F630` →
**`addss xmm0,[eax+0x108] / movss [eax+0x108],xmm0`**（车身刚体的力累加器 `+0x108/+0x10C/+0x110`）。

## 4. 原生逐帧管线（地址级）

### ① 轮胎状态数学 `0x45A610`（叶函数，全程无 call）
入口 `edi = 车`；`[edi+0x24d4]`、`[edi+0x22c0]==7` 为前置门控。
开头就是**3×3 矩阵 × 3 维向量**（矩阵行 `+0x68/+0x78/+0x88`，向量 `+0x50/+0x54/+0x58`）。
在 `0x45ad5b` 读 **轮荷 `[edx+0x114]`**，随后 `0x45ad94` 读系数、`0x45adb6` 循环累加 `acc += coef[2]·load`
（docs/40 §1.2 已记）。

### ② 悬挂解算器 `0x469FE0`（含 SEH，帧 0x144）
逐轮循环头 `0x46AEE0`，回边 `0x46b060 jl 0x46aee0`；`ebx += 0x1528`；边界 `[edi+0x3cb0]`。

核心（`0x46af20` 段，逐字对应）：

```asm
movups xmm4, [eax+0x68]        ; 胎半径
divss  xmm1, [eax+0x5c]        ; ← 除以胎簧刚度（Java setTyre 写的）
divss  xmm2, [esi+0x38]        ; ← 除以弹簧力（Java setForce 写的）
comiss xmm4, xmm1 / ja         ; 若 半径 > 胎变形 则取 胎变形  ⇒ 变形被钳在半径内
movss  [eax+0x138], xmm0
movss  [eax+0x114], xmm0       ; ★ 轮荷落盘
movss  xmm0, [esi+0x44] ; addss xmm0, [esi+0x58]   ; 自由长
subss  xmm0, xmm2 ; subss xmm0, xmm1               ; − 悬挂变形 − 胎变形
subss  xmm0, [esi+0x6c]*[esp+0x38]                 ; − 阻尼项 ⇒ 悬挂长度
movss  [eax+0x134], xmm0
or     [ebp+0x54], 0x100000 / 0x200000             ; ★ 置接触/滑移状态位
```

### ③ 接触几何解算器 `0x464F80`（帧 0x398，约 6.6KB）
门控：`test [车+0x54], 0x300000; je → 直接返回`。
内容：接触点投影（`fsqrt`/`fabs`/`fdivr` 归一化）、用**刚体旋转矩阵**（`[ebx+0x14b4]…[ebx+0x14d0]`）
把力/向量变换到世界系、把位姿 + `R[12]` 提交（`0x46651e–0x466548`）。
本函数只出现 8 个 call，全在 `0x42/0x56/0x67` 数学与对象辅助区 —— **没有任何物理 API 调用**
⇒ 力的施加不在这一层。

### ④ 关节件创建 `0x4326D0` —— ✗ **上一版读错了，此处更正**

调用点两处：`0x4A4B0F`、`0x4A4F22`，**两边都是**
`mov ecx, [ebx+0x6c]; add ecx, <逐次偏移>; call 0x4326d0`（5 个参数）
⇒ 被喂的是 **`[ebx+0x6c]` 里的部件数组**（按部件逐个处理），**不是**每轮的质点。

函数体实读（`0x4326D0`，长 0x3D0 = 到 `0x432AA0`）：

```asm
push 0x3c / call 0x66659d          ; ★ 分配 60 字节
mov  [eax], 0x6ef750               ; ★ vtable → 唯一虚函数 0x4A3A30
mov  [eax+4..+0x14], 0            ;    链表 prev/next/owner
...
mov  [ecx+0x18..0x20], <arg1 vec>  ; 锚点 1
mov  [ecx+0x24], <arg2 float>      ; 半径/质量一类标量
mov  [ecx+0x28..0x30], <arg3 vec>  ; 锚点 2
mov  [ecx+0x34], arg4 / [ecx+0x38], arg5
```

★ 定位它的**唯一判据**：vtable 紧跟的字符串 —— `0x6EF750` 处是
`0x004A3A30`（析构），其后立刻是 **`"uninstall error: jointed part!"`**（`0x6EF754`）。
同族字符串：`install error: undefined joint type: %d`、`install error: non-jointed part!`、
`uninstall error: non-jointed part!`、`part_install: missing target slot (%d)!`，
以及命令名 `cbone` / `pbody` / `rod` / `rodz` / `cylinder` / `sphere`。
⇒ 这套东西是**车用部件（wing / rollbar / rod / link）的关节附着**，与轮胎受力无关。

**上一版在这里犯的错**：把 `[part+0x24]` 当质量、`[part+0x28..0x30]` 当 `F/m` 累加器，
于是把「两件相互穿透后的分离修正」误读成「力累加」。教训：**先定对象身份（vtable+字符串），再读字段**。

该段的**正确读法**（`0x432a3a`，两件穿透后的分离修正 —— 不是力累加）：

```asm
movss xmm0, [ecx+0x24]         ; 已存在件的半径（新件半径在 xmm4 / 已被比过）
divss xmm0, [edx+0x24]         ; ÷ 新件半径 ⇒ 半径比（重叠深度按半径比例分配）
movss xmm1, [esi]   ; 分离方向 x（由锚点差归一化而来）
mulss xmm1, xmm0
addss xmm1, [edx+0x28]         ; 锚点 2 x 上做修正量累加（分离，不是受力）
movss [edx+0x28], xmm1
... 同理 [esi+4]→[edx+0x2c]、[esi+8]→[edx+0x30]
movss [edx+0x24], xmm4
mov eax, [ecx] ; push 1 ; call dword ptr [eax]   ; ★ 虚调用 = 通知/唤醒对应引擎对象
```

⇒ **对象状态**：`半径/标量 @+0x24`，`锚点 2 @+0x28..+0x30`（被分离修正量改写），`锚点 1 @+0x18..+0x20`。
**它属于部件关节系统，与「力→刚体」无关**（力的机制见 §8）。

### ⑤ 逐项施力 `0x45B010`（3 参数，从 `[车+0x1508]` 链表逐项调用）
帧 0x114。开头 `mov ecx,[ebx+0x28]; add ecx,0x28` 后两次 `call 0x4BB100`（沿轴投影），
再用 `[obj+0x68]` 的 3×3 矩阵乘 `[ebx+0x30/+0x34/+0x38]` 向量 ⇒ **局部力 → 世界系**。

### 11.2 时间推进 `0x4B79A0(world, dt)`

```asm
0x4b79a0  movss xmm0,[esp+4]        ; dt（帧时长）
0x4b79a6  movss xmm2,[0x6ebf8c]     ; ★ 阈值 = 1e-4
0x4b79b1  addss xmm0,[esi+8]        ; acc += dt
0x4b79bb  comiss xmm2, xmm1
0x4b79c9  ja   0x4b7a1e             ; ★ 若 acc < 1e-4 → 本帧不步进，直接返回 0
0x4b79cf  movss [esi+8], xmm0(=0)   ; 清累加器（subss 自减）
0x4b79d8  movss [esi+0x10], xmm1    ; ★ world+0x10 = 本步实际 dt
0x4b79dd  addss xmm0,[esi] ; movss [esi+4],xmm0   ; world+0x04 = world+0x00 + dt
0x4b79e6  inc   dword ptr [0x77a254]  ; ★ 全局步数计数器
0x4b79ec  [esi+0x14]=0 [esi+0x18]=0 [esi+0x70]=0 [esi+0x98]=0   ; 清四个字段
0x4b79fb  call  0x4b7820            ; 清理 world+0xDC 链表（虚调用判活，返回负则摘除；dec world+0xA0）
```

**⇒ 不是固定子步进：每帧推进一次，dt = 帧时长 + 残留，仅受 1e-4 下限保护。**
（`[0x6EBF8C] = 1e-4`；`[0x77A254]` = 全局步数，在 `0x4A9046` 被清 0。）

### 11.8 ★ 力的第三个写点：`0x682490`（刚体虚表 slot#8，x87 路径）

**为什么之前一直扫不到**：全库用字面偏移 `+0x108` 做**SSE** 读写的函数只有 `0x67F630`（addForce）、`0x67F680`（addTorque）

### 11.10 ★ 重力的施加点（本轮实锤）：`0x6B2280` 段

在 `0x6B1B50`（接触/受力大函数）内部，对每个刚体做**重力累加**（未展开 ×3，步长 4 字节）：

```asm
0x6b2280  ecx = [ebp-0x2c]                      ; 刚体个数
0x6b2294  test byte ptr [edx+0x18], 8           ; ★ body+0x18 位 3 = "跳过"（静态/睡眠体）
0x6b229b  jne 0x6b22f4                          ; 跳过该体
0x6b22a0  movss xmm0, [edx + 0x20]              ; ★★ body+0x20 = 质量
0x6b22a5  mulss xmm0, [ecx + 0x28]              ; ★★ [参数结构+0x28] = 重力 x
0x6b22aa  addss xmm0, [edx + 0x108]             ; facc.x
0x6b22b2  movss [edx + 0x108], xmm0             ; ★★★ facc.x += m·g.x
   … 同形：×[ecx+0x2c] → +0x10c（g.y）、×[ecx+0x30] → +0x110（g.z）
```

**结论**：
* `facc`（`body+0x108/+0x10c/+0x110`）确实是积分器的输入 —— 引擎专门给它喂重力。
* 重力向量由**参数结构**传入（`+0x28/+0x2c/+0x30`），不是从世界对象读的。
* 刚体新增两个字段：**`+0x18` = 标志（位 3 = 跳过/静态）、`+0x20` = 质量**（标量）。
* 这也解释了 §11.1 里 `0x4B2B90` 传的 `Vec3* out` 与 `0x4B1640` 一类 ctx 的角色（参数打包）。

### 11.11 ★★ 力的消费端：求解器区 `0x6Axxxx–0x6Cxxxx`，**不是**显式欧拉

**判定依据（三处实读）**：

**(a) 线性方程组装配** `0x6A1130` 段（函数 `0x6A0E70` 内）：
```asm
0x6a1130  movss xmm3, [esi + edx*4 + 0x118]    ; tacc[j]（edx 为轴索引，步长 4）
0x6a1142  mulss xmm3, xmm0
0x6a1146  addss xmm3, [esi + 0x108]            ; ★ xmm3 = facc.x + Σk tacc[k]·M[k][0]
0x6a1152  addss xmm4, [esi + 0x10c]            ; ★ … + facc.y
0x6a115e  addss xmm5, [esi + 0x110]            ; ★ … + facc.z
0x6a1166  清零栈缓冲：edx = 0,0x10,…,0x100（步长 0x10、跨度 0x100）
          → 两组 16×3（或 16×4）矩阵：A @ [esp+0x104]、B @ [esp+0x204]
```
⇒ **力/扭矩被装配成线性方程组的右端项（b = facc + T·tacc），方程组规模 16 行**。这是直接/隐式求解，不是逐体标量积分。

**(b) 工作区对象（不是刚体）**：`0x6A0460` / `0x6A0E70` 的 `esi` 是一个**求解工作区**，
字段 `+0x200`/`+0x204` = **两个刚体指针**，`+0x00..0x48` 缓存 A 体姿态矩阵与位置、`+0xD8..` 缓存 B 体矩阵、
`+0x108` **在该工作区里是"对手体位置"**（`0x6A0545` 取 `[esi+0x200]` 的位置后写 `[esi+0x108]`）。
⇒ ★ **此处 `+0x108` 与刚体的 facc 同偏移不同物**，是第三例偏移撞车（前两例见 §11.5/§11.8）。

**(c) 回代形状** `0x6BB550`：
```asm
0x6bbe34  xmm0 = [esi+0x64]·[eax+4]
0x6bbe3e  xmm1 = [esi+0x70]·[eax+8]
0x6bbe4c  xmm1 = [eax]·[esi+0x58]
0x6bbe59  addss xmm0, [esi+0xa0]
0x6bbe61  movss [esi+0xe8], xmm0            ; ★ lvel.x = 行0(M)·v + t.x
0x6bbe96  …                          → +0xec   （行1：+0x68/+0x5c/+0x74，平移 +0xa4）
          …                          → +0xf0   （行2：+0x6c/+0x60/+0x78，平移 +0xa8）
0x6bbfe5  xmm1 = [esi+0x6c]·[edx+4]
0x6bbff9  xmm1 = [esi+0x78]·[edx+8]
0x6bc007  addss xmm0, [esi+0xa8]
0x6bc00f  movss [esi+0x108], xmm0           ; ★ 同一矩阵的另一行 → 写力槽
```
⇒ 刚体的 **3×3 矩阵在 `+0x58`（行距 `0xC`：0x58/0x64/0x70 · 0x5c/0x68/0x74 · 0x60/0x6c/0x78）**，偏移向量在 `+0xA0/+0xA4/+0xA8`；
求解把结果**按行分别写进速度槽（+0xE8）与力槽（+0x108）** —— 线性系统回代的典型形状。

**⇒ 对重制的影响（★ 重要结论，供规格书使用）**：
原引擎的物理推进**不是** `lvel += facc/mass·dt` 的显式欧拉。它是：
1. 各来源往 `facc` 累加（轮胎/悬挂由游戏侧、弹簧/约束、**重力由引擎 0x6B2280**）；
2. 每步**装配 16 行的线性方程组**（`b = facc + T·tacc`，栈上 `A[16]`/`B[16]`）；
3. 直接求解/回代，结果写回速度与力槽；
4. 接触用**冲量**在 `0x6B1B50` 里解（不是力）。
⇒ 重制要么复刻这个块求解器（需要 dt、质量 `+0x20`、矩阵 `+0x58` 的来历），
要么承认「手感由约束求解器决定」并用等效参数拟合。

### 11.16 ★ 自我纠正：`+0x108` 的第三例撞车

§11.11 里把 `0x6A1130` 段的 `[esi+0x108]` 读成"刚体 facc"是**错的**。该处 `esi` = **工作区**，
其 `+0x108` 是 **对手体（A 体）的位置**（`0x6A0545` 取 `[esi+0x200]` 的位置后写入）。
所以那段是「用两体位置/矩阵装配杠杆臂与行累加器」，**不是** `b = facc + T·tacc`。

⇒ 至此 `+0x108` 的撞车共 **三例**：工作区的位置字段、`0x43E8B0` 的浮点+字节结构、`0x682490` 的力源。
**判据教训**：只看偏移一律会错；必须**同时看该字段在几行之前刚被谁写入**（`0x6A0553` 一读就露馅）。

### 11.17 ✗ facc 消费端的最终状态（本轮收窄后的诚实结论）

**所有** `0x108` 引用（464 处，全 `.text` 穷举）归入四类，**没有一类是"读 facc → 写速度"**：

| 类别 | 代表 | 说明 |
|---|---|---|
| 喂 facc（力源） | `0x67F630`（应用层 addForce）、**`0x6B2280`（重力 `facc += m·g`）** | 已实锤 |
| 写 facc（覆盖/清零） | `0x682490`（`0.5·(P₁+P₂)`）、**`0x6B84D0`/`0x6BB550` 各 6 处 `movups [r+0x108]` = 2 体 × 3 分量清零**、`0x6C0FB0` | 说明这些函数**处理** facc，但是**后置清零** |
| 同偏移不同物 | 工作区 posA、`0x43E8B0` 的字节结构、`0x44F350`（序列化读 facc 打文本） | 假线索 |
| 无关 | 其余（局部变量/结构字段） | — |

⇒ **`0x6B84D0` / `0x6BB550` 都在同一个求解循环里对两体各做一次 `movups [body+0x108]`（3 分量）清零 ⇒ 它们就是"用完 facc 就清"的求解器**。
力的读取环节应在这两个函数的**更深一层调用**里（或经 `+0x7C`/`+0x80` 缓存的指针），而不是它们自己的顶层代码。

**下一步（写给下一轮，按性价比排序）**：
1. **读 `0x6B84D0` 与 `0x6BB550` 的头部**（`+0x50`/`+0x64` 几何链是否出现 ⇒ 判定是否处理刚体），并**在其调用树里搜 x87/打包读 facc**（`fld [r+0x108]`、`movups xmm,[r+0x108]`）—— 判据要沿调用树下潜一层。
2. **`0x6C0FB0`**（3216 B）与 `0x6B60A0`（1744 B，读 `+0xF0/+0xFC/+0x108` 做 min/max）—— 后者的 min/max 用法像**扫掠包围盒/运动限幅**，可顺带定出速度分量偏移。
3. **`0x67E303` 所在函数**（注册处）的调用者 → 引擎步进的最外层（谁把交互回调表装进求解器）。
4. 若仍不闭合，改从**运行时**取证：在 `0x6B84D0` 入口下断，看谁把 facc 变成 lvel（但用户不要求上机，留作备选）。

### 11.19 `0x6BB550` / `0x6B84D0` 的性质（本轮实读头部）

两者同族（`and esp,-8; sub esp,0x64/0x6c`，`esi` = 求解工作区，`ebx`/`edi`/`ecx` = 输入）：

```asm
0x6bb561  movsx eax, word ptr [ebx]        ; ★ 输入是 int16 序列
0x6bb564  movsx edx, word ptr [ebx+2]
0x6bb577  movsx eax, word ptr [ebx+4]
0x6bb595  movzx edx, word ptr [ebx+6]      ; 混用有/无符号
0x6bb56b  cvtsi2ss xmm0, eax               ; ★ 转 float
0x6bb56f  mulss xmm0, [esi+0xb8]           ; ★ 乘比例因子（+0xB8/+0xBC/+0xC0/+0xC4/+0xC8/+0xCC/+0xD0/+0xD4 共 8 个）
0x6bb5d7  movsx eax, word ptr [ecx]        ; 第二组 int16（同一张比例表）
0x6bb616  movss xmm0, [esi+0x7c]           ; 3×3 矩阵行（+0x7C/+0x88/+0x94 …）
0x6b84f0  eax = [esi+0x28]; inc; [esi+0x28] = eax   ; ★ 迭代计数器
0x6b853e  subss xmm2, [ebx]                ; 仿射式求值
0x6b856d  and ecx, 0x7fffffff ; cmp ecx, edx ; ja 0x6ba417   ; ★ |x| 与限值比较 ⇒ 夹取/超限分支
```

**判读（推断处已标注）**：
* 输入是 **2 组 × 4 个 int16**（`movsx/movzx word` + 8 个 float 比例因子）⇒ **一组 4 元量化数据 = 四元数**，两组 = 两个姿态
  ⇒ 这两函数在**从量化输入重建姿态**并做约束/限幅求值；`+0x28` = **迭代计数**，`|x| > limit` = **夹取**。
* 它们对两体各做一次 `movups [body+0x108]`（3 分量）= **用完即清 facc**（§11.17），故属于求解链，而不是"喂力"。
* ⇒ 引擎的求解层使用 **int16 量化 + 标量比例表** 的表示（重制时可忽略量化，但要知道原版有这一步精度损失）。

## 12. 引擎全局物理单例 + 逐类型约束内核族（本轮新增）

### 12.1 ★ 读取 facc 的内核族（8 个等距函数）

穷举 `+0x108`（464 处）时漏看的一族 —— **8 个结构同源、地址等距的求解内核**，每个**恰好一条** `facc` 访问，
且**8 处指令字节完全相同**：`F3 0F 58 86 08 01 00 00` = **`addss xmm0, dword ptr [esi+0x108]`**（标量、读）。

| 内核 | 指令地址 | 内核 | 指令地址 |
|---|---|---|---|
| `0x6C1C40` | `0x6C21B2` | `0x6C3FC0` | `0x6C4531` |
| `0x6C2650` | `0x6C2BC0` | `0x6C4CD0` | `0x6C5242` |
| `0x6C2DC0` | `0x6C3374` | `0x6C5470` | `0x6C5A22` |
| `0x6C3810` | `0x6C3DC1` | `0x6C61B0` | `0x6C6763` |

（核对法：对 8 个函数区间扫 `f3 0f 58 .. <disp32 0x108>`，命中即上表；**前缀 `F3` 决定它是 `addss` 而非 `addps`**，
本轮第一次扫时正则窗口切掉了 `F3`，才误写成 `addps`，此处已订正。）

| 关于 `body+0x108` | 结论 |
|---|---|
| 写入者 | `0x67F630`（应用层力）、**`0x6B2280`（重力 `facc += m·g`）** ✓ 实锤 |
| **读取者（刚体）** | **仍未定位**。本轮 8 个内核 + `0x6C0FB0` 全是**全局对象**的 `+0x108`，不是刚体的 |

⇒ 同一偏移的**第五次**撞车说明：**刚体 facc 的消费很可能不经过 `[reg+0x108]` 形态**。
最可能的两条剩余路径：
1. **经缓存指针**：ctor `0x681520` 已把 `&pos`/`&q` 缓存到 `+0x84/+0x88`，同类手法可能把 `&facc` 缓存到某字段，

   真正的速度由冲量积分得到 —— 这需要下一轮**在 `0x6B84D0`/`0x6BB550` 的入口下断**（需上机）或
   继续穷举 `+0x7C/+0x80/+0x84/+0x88` 指针字段的构造函数来定。

### 13.4 ★ 假线索清理：SIB 形态（本轮第六次更正）

`0x46E770` 里 4 处"宽读 facc"实为 **`movss xmm, [esp+eax*4+0x108]`（栈数组 + SIB）**：

```
0x472a91: f3 0f 10 bc 84 08 01 00 00   ; modrm=BC(mod2,rm=4→SIB), SIB=84, disp32=0x108
                                          ; ⇒ [esp+eax*4+0x108]，不是 [reg+0x108]
```

**扫描规则修正（已入技能）**：modrm 的 `rm` 位为 `100` 时必须跳过（SIB 形态），
否则栈/SIB 数组会被误判成结构体字段。本质与"偏移撞车"同类：**只凭 disp32 无法定位字段**。

### 14.9 ★ 缩放因子 `arg6` 的性质（推断，已标注）

`0x6B1B56`–`0x6B1B5E`：

```asm

```

`arg6` **按 float 参与 `divss`** ⇒ 不是计数、不是指针。两种候选：

| 候选 | 含义 | 支持 | 反对 |
|---|---|---|---|
| **dt**（更可能） | `Δv = 逐体行量 / dt` ⇒ **Baumgarte 式位置误差→速度修正**（`C/dt`） | 单次调用只有一个标量；dt 已在碰撞实参链上（§14.8）；接触求解经典做法 | 需要行量为"位置误差"量纲 |
| 质量 | `Δv = 冲量 / m` | 冲量式求解器的标准形式 | 质量应逐体，不会是单个标量 |

⇒ **重制规格里建议按 `Δv = 行量 / dt` 建模**，并把"行量"视为上游（§14.5 的 8 个行内核）输出的每体 6 分量
（`lvel(3) + avel(3)`，缓冲步长 `0x18` = 6 float ✓ 实测 `add ecx, 0x18`）。
**残余不确定**：`0x69A000` 内部对回调的实参逐项未读（下一轮 1 处即可定案）。

### 13.5 ✗ facc 消费端：上一轮的收敛结论（已被 §14 翻转）

把 `[reg+0x108]` 的可能性穷尽到"**真·非 SIB 的 128 位宽读**"这一层后，名单是：

`0x44F350`(序列化) · `0x45A610` · `0x4B0510` · `0x535510` · `0x535C00` · `0x5DF1E0` · `0x5E3B50` ·
`0x5E89A0` · **`0x680580`(链表插入，假)** · **`0x680810`(addForce 体坐标系)** · **`0x680960`(addTorque)** ·
`0x682490`(力源) · `0x6A0460`/`0x6A0E70`(工作区) · `0x6B1B50`(重力) · `0x6B60A0`(min/max)

**⇒ 无一处是"读 facc → 写 lvel"。** 至此已排除全部字面偏移形态（标量 SSE / 打包 SSE / x87 / 指针缓存 / 宽读 / SIB），
结论收敛为：**原版大概率在求解器内部以冲量形式消费外力，而不是把 facc 显式积进 lvel**。
验证只剩两条路：
1. **在 `0x6B84D0` / `0x6BB550` 入口下断**，看 `[body+0x108]` 是否被读（需上机）；
2. **换方向**：不追 facc，改追**冲量**（`0x6B84D0`/`0x6BB550` 里被写进速度的量从哪来）—— 这是纯静态可做的，
   且对重制规格更有用（冲量模型 = 可直接复现的公式）。



* **读 vs 写由操作码决定，不由偏移决定**：`F3 0F 58`= `addss`(读)、`F3 0F 11`= `movss`(写)、
  `0F 58`= `addps`(读)、`0F 11`= `movups`(写)。上一轮把「`0f 58`(读)」与「`0f 11`(写)」混列成一行，
  于是把 8 个**读者**当成"用完清零器"，白白错过一轮。
  **且正则窗口要留够前缀字节**：`F3` 被切掉就会把 `addss` 读成 `addps`（本轮发生并已订正）。
* **静态初始化桩 = 全局单例地图**：扫 `b9 <imm32> e8/jmp <rel32>` 就能拿到全部全局对象 + 构造函数
  （虚表从 ctor 的 `mov dword ptr [esi], <imm>` 直接读）+ 析构函数。析构器会遍历清零你正在找的字段，
  是极有说服力的假阳性 —— 必须靠这张表区分。
* **`ecx = <绝对地址>` 是判断"this 是全局单例"的决定性证据**：`mov ecx, 0x8DF990` 一出现，
  该函数操作的就是静态对象，与堆上的体无关。

### 11.20 方法论（上一轮教训，已同步进技能）

* **偏移量不能当身份**：`+0x108`、`+0x144`、`0x1D4` 这类偏移在 3MB 的二进制里遍地都是；有效判据是
  **读-改-写对**（`addss xmm,[d]` + `movss [d],xmm`）、**虚表槽**、**分配器实参**（`push 0x3c/0x50/0xa4` = 结构体大小）。
* **`.data` 的 vsz > rsz 区段直接读文件会得到垃圾** —— 先查段表再下结论。
* **不要用宽正则搜关键词**（本次 `step|update` 把整片 GUI 类淹了）：用精确词或精确符号。
