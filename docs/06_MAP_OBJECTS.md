# P3.6 —— 地图物体表（`RSD` 明文块）

> 状态：**已解并全量导出**。这是本次逆向里**对重制最直接可用**的产物。

## 1. 那 8.7 MB 里是什么

之前把 coastline 的 11 MB 块当作"顶点流"，只解释了 21%。
用「排除法」把已确认的 44 字节顶点记录剔除后，对剩下的 8.7 MB 做画像：

* 熵 **6.69 bits/byte**，zlib 只压到 **43%** → **不是压缩数据**（压缩数据会接近 8.0 且压不动）
* 每个偏移上"有限浮点"的比例都是 51%，没有 44 字节周期结构 → 不是第二种顶点格式
* u16 直方图弥散（50% 落在 4096–32767）→ 也不是索引数据
* 直接 dump 原始字节 → **一眼看到明文**：

```
+0000  62 6c 65 5f 6c 61 6d 70 00 ...
+0040  00 52 53 44 00 48 00 00 00 67 61 6d 65 74 79 70
+0050  65 20 30 78 30 30 30 33 30 30 35 30 0d 0a 70 61
+0060  72 61 6d 73 20 2d 33 37 2e 37 34 39 2c 37 35 2e
```

## 2. `RSD` 块格式

```
"RSD\0" ; u32 size ; size 字节 ASCII 载荷
```

载荷固定两行（`\r\n` 分隔）：

```
gametype 0x00030050
params -37.749,75.271,-294.362,0.363,0.000,0.000
```

* `params` = **位置 (x,y,z) + 旋转 (rx,ry,rz)**
* 实测 size 分布：`72`(4215)、`73`(3622)、`71`(2843)、`74`(1639)、`70`(1626)…
  —— 全部 70–76 字节，因为浮点数字面长度不同

还有一类变体，`params` 是**文件名引用**：

```
gametype 0x00010035
params 0x00000004,0,0,0,0,0,0,maps\boulevard\meshes\track.scm
```

→ `0x00010035` 是**「挂载这个网格文件」指令**，直接给出了网格路径。

## 4. `RSD` 块之间的二进制记录

同一区域里还有**带名字的场景实例**，格式为
`<名字串> <6×f32 位置/旋转> … <u8 nameLen> <名字>`：

```
+0000  "668\0"
+0004  f32 650.2785, 54.9800, -88.5679, 3.0947, 1.5200, 1.7911
+0030  u32 0, 0x0B6E, 0x0450, 0x2101, f32 1.0, u32 0x006A7BE5, u32 0x57
+0041  u8 7, "Box667\0"
```

名字实例：`Box667`、`l_flare202`、`ble_lamp`（= `double_lamp`）、`668` …
—— 这些是**摆放好的道具实例名**，配合场景目录（P3.4）的物件类型表即可完整重建场景。

## 6. 对重制的意义

* **每个地图的每个物体都有精确坐标 + 朝向** —— 不需要靠猜重建关卡布局
* `gametype` 是**离散的物件/事件枚举**，全游戏只有 ~40 种常用值
  → 在 Unity/Godot 里实现这 ~40 个 `gametype` 的生成器，就能装配全部关卡
* `gametype 0x00010035` 直接给出网格文件路径 → 物件与网格的绑定关系是现成的
* 输出坐标系与 INVO 网格、coastline 顶点流**同一套**（对比坐标量级与地图名即可确认）

## 7. 仍缺

* `gametype` 编号 → **游戏内物件名的映射表**（需要反汇编或对着游戏内截图逐一确认）
* `RSD` 块周围的二进制记录（`0x0B6E` / `0x0450` / `0x2101` 这类字段）语义未定
* coastline blob 内仍有一部分既非顶点记录也非 `RSD` 的字节（主要是各顶点数组的 u16 索引列表）
