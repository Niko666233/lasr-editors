# 41 · 轮胎系统重制规格（翻译层）

> 目的：把 `docs/19 / 20 / 35 / 37 / 38 / 39 / 40` 的逆向结论**压缩成一份可直接实现**的规格。
> 面向「在现代引擎里重做同一套手感」。凡未确证的都以 **✗ 未知** 标出，并给出**安全缺省**。
> 数值单位按原生二进制原样给出（未做量纲换算 ✗）——换算需实机标定。

## 1. 数据结构（三层，别混）

```
车辆对象 (Vehicle)
  ├─ count @ +0x58            // 轮/条目数
  ├─ pacdata 指针 @ +0x330     // ★ 指向运行时系数块（不是内联）
  └─ 主系数表 @ +0x4880        // 32 条 × 144 B（初始化时装载）

运行时系数块 (pacdata，堆上，分配 0x900 = 2304 B)
  └─ 16 条 × 144 B，每条 36 个 f32  ← 槽 0..35

轮胎子对象 (per wheel)
  └─ 步长 0x1528，内联系数块 @ +0x20C（36 个 f32）
     ★ 数组基址 = [车 + 0x20a4]，轮数 = [车 + 0x3cb0]（docs/44 §2.1）
     ★ 本对象 +0x24 → 轮胎物理子结构（载荷/长度/刚度/半径…，docs/44 §2.3）
     ★ 本对象 +0x38 = 弹簧力（Java `setForce` 写）
```

**系数索引**：`coef(entry, slot) = base + entry*144 + slot*4`

| 数字 | 含义 | 独立旁证 |
|---|---|---|
| **144 B** | 一条 = 36 f32 | `docs/20` 写入端；`docs/35` 索引上界 35；`docs/38` `push 0x90` |
| **36** | 槽数 | 上面三条 + `docs/40` 的 `entry*144` |
| **16** | 运行时 pacdata 条数 | `docs/39` 分配 `0x900`；`PacejkaGlobals.pacVarIdxs` 16 项 |
| **32** | 主表条数 | `docs/38` `cmp esi,0x20`；`docs/20` 参数校验 `[0,32)`；`MapTrack.mapper` 32 项 |
| **0x1528** | 轮胎子对象步长 | `docs/40` `add esi,0x1528` |

## 3. 已实证的公式片段（`docs/40`）

```
// 载荷归一化（两处独立）
nl = min(1.0, load / coef[11])          // 1.0 截顶

// 滑移 + 悬挂行程 的合成尺度（x87 逐条仿真已核对，见 docs/40 §1.4）
s = sqrt([sub+0x148]) + 10.0 * |[sub+0x134]|      // ★ 旧版「sqrt(a²+b²)+20×」有误

// 两段式（断点 5.0）
s = (s < 5.0) ? (s / 5.0) * nl : nl

// 抓地力累加
acc += coef[2] * load                    // 循环所有轮位
```

常量：`[0x7426C0]=5.0`（断点）、`[0x7426C8]=10.0`（**乘数**，不是断点）、
`[0x6E7A70]=0.1`、`[0x6E7A74]=0.01`、`[0x6EC24C]=0.05`、`[0x6E766C]=1.0`。
★ `[0x7426C4]=20.0` 存在但该函数**不引用**。

★ `[sub+0x134]` **已定名 = 悬挂当前长度**（写点 `0x46af71`），不再是「滑移分量」。
详见 `docs/44` §2.3。

## 4. 配方 ↔ 地面（`docs/35`）

* 6 个接触面：`Asphalt / Grass / Gravel / Hard_Sand / Snow / Ice`
* **9 种普通胎只靠槽 2 区分地面**；`XD`/`XD_B`（越野）额外改槽 **0 / 2 / 11 / 13 / 19**
* µ（槽 2）实测：沥青 `RS 2.25 … XD 1.2`；冰面为沥青的 **5–23%**
* 品牌 ↔ 等级：`RS`(ECSTA S700) > `RM`(V102) > `RH`(ADVAN) > `SS`(RE050A) >
  `SM`(RE070) > `SH`(Potenza) > `XD_B`(Dueler M/T D673) > `NC`(P400 Touring) > `XD`(T/A KO)
* Java 侧紧凑序 → 真槽号：`pacVarIdxs_v2`(18) / `v3`(20)；
  `pacVals_N ≡ 槽 pacVarIdxs_v3[N]`（`docs/38` §6.1）
* ★ **`common_pacVarIdxs` 会运行时覆盖**槽 15/16/22–26（`docs/39` §2.2）

## 5. 重制实现建议（按优先级）

1. **先做数据层**：直接采用本表 + `out_tyres_slots.csv`（66 行：11 配方 × 6 面 × 36 槽）。
2. **公式按 §3 实现**，滑移/载荷的**量纲**需实机标定（✗ 原版单位未定）。
3. **槽 3 不要当常量**：它每帧被算出来写回（语义未定 ✗）——先按「由滑移/载荷推出的
   修正项」占位。
4. **未知槽的安全缺省**：`1,5–10,17–20,27,29,31,32,34,35 = 0`；`21 = 1.0`；
   `28 = 0.1`；`30 = 0.5`；`33 = 1000`。**照抄默认值比乱猜安全**。
5. **别做逐帧 `setFrequency` 式的过度还原**（音频侧已证伪，见 `docs/34`）；
   轮胎这边的对应教训是：**槽 2 与槽 3 是运行时覆盖字段，不要写死在配方里**。
