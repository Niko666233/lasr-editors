# 56. 零件槽的几何来源（谁给物理槽位姿）

> 承 `docs/55 §3`（槽位系统的两半：`slotLookupTable` / `part_attach`）：那里解决了「零件装到**哪个槽**」，
> 本文解决「这个槽**在哪儿、朝向如何**」——即 `SlotMap.slot`（物理槽 id）的刚体变换从哪来。
> 工具：`tools/slot_geometry.py` → `out_slot_geometry.json` → `remaster/data/slot_geometry.json`（21 个数据集之一）。

## 0. 结论（一句话）

**位姿不由槽位表提供，而由字符串字面量 `configureType("slot\t\t<pos>\t\t<rot>\t\t<id>")` 提供**：
车辆的 `Model_*.java` 声明**骨架槽 + 默认装配件**的位姿；**造型件由零件类自带位姿**（换 `style_I` 就换位置/形状）；
而**纯参数件（引擎/变速箱/差速器/排气/氮气/悬挂/传动）一个 `configureType` 都不调** ⇒ 它们占的物理槽**没有几何**。

数一览（`remaster/tools/validate.py` 已逐项断言）：

| 量 | 值 |
|---|---|
| 扫描类 | 1884 |
| 声明了 slot 的类 | **691** |
| `configureType` 调用数为 0 的类（纯参数件） | **1193** |
| 「有 slot 声明却无其它 `configureType`」的类 | **0**（几何类必有网格类配置） |
| 被声明的物理槽 id | 46 |
| 槽位表引用的物理槽 | 63 |
| ├ 有几何 | **46**（其中 32 个被表引用） |
| ├ 逻辑槽（有零件、无网格） | **12** |
| └ 死槽（游戏无对应零件） | **19** |
| 声明但未被槽位表引用（模型内部硬点） | 14 |

## 1. 声明格式（★ 含解析陷阱）

`out_pseudo/**/vehicles/**/*.java` 里的字符串字面量（`\t` 是转义两字符）：

```
configureType("slot\t\t<x y z>\t\t<rx ry rz>\t\t<id>")
```

真实例子（`Coupe_TornadoR_Muffler_stage_I`，3 行 = 3 个槽）：

```
"slot\t\t0.0 -0.0639233 -0.111006\t0.0 0.0 0.0\t4130\t; muffler"     ← 消音器
"slot\t\t-0.531563 -0.0183848 0.165327\t0.0 0.0 0.0\t403\t; exhaust_l" ← 左尾段
"slot\t\t0.532 -0.0183848 0.165482\t0.0 0.0 0.0\t404\t; exhaust_r"     ← 右尾段
```

- **字段序**：位置 (3 float) → 朝向 (3 float) → **id**；朝向是欧拉角，右灯条用 `3.142`（= π）翻转（`vehicles.classes.CTF_Lightbar` 的槽 1/2）。
- **★ 陷阱**：行尾可能有 `\t; 注释`，注释里也可能有数字。**必须取「第 7 个数字」**，不能取「最后一个数字」
  （早期版本取末位，把 `; exhaust_1` 的 `1` 当成槽 id，凭空造出两个假槽 → 已修，见 `tools/slot_geometry.py:parse_slot_lines`）。
- 少数行只有 6 个数字 ⇒ 跳过（不是合法 slot 行）。

## 2. 谁声明（两类声明者）

| 声明者 | 数量 | 例子 | 语义 |
|---|---|---|---|
| 车辆模型 `Model_<车>` | 20 个类 | `Model_Coupe_RS`、`Model_Hatch_S2_WB` | **骨架槽**（车体硬点）+ **默认装配件**的位姿 |
| 零件类 `<车>_<件名>_<变体>` | 671 个类 | `Coupe_TornadoR_F_Bumper_style_I`（槽 1000） | 造型/结构零件**自带**占用槽的位姿 |
| 共享模型类 | 1 个 | `vehicles.classes.CTF_Lightbar` | 灯条的左右两个子槽（id 1 / 2） |

**骨架槽 id（37 个，`Model_*` 声明）**：
`101-104, 131-134, 402-405, 911, 912, 1000, 1010, 1020, 1021, 1030, 1040, 1100, 1101, 1110, 1111, 1120, 1121, 1130, 1131, 1140, 2100, 2101, 2120, 2220, 4130, 9997, 9998, 9999`
（编号有语义分组：1xx = 悬挂/铰点、4xx = 排气、9xx = 特例、1xxx = 车身外观件、2xxx = 内饰、4130 = 消音器、999x = 特殊件）

**零件类独有 id（9 个，车辆模型不声明）**：
`1, 2`（灯条左右，来自 `CTF_Lightbar`）、`100`（轮毂）、`2000, 2001`（`Coupe_ZX`/`Coupe_RS` 的车门槽——**别的车用 1110/1111**）、`3140, 3141, 3240, 3241`（轮胎，前后轴各 2）。

**声明了但槽位表从不引用（14 个）**：`1, 2, 100, 131-134, 402-405, 911, 912, 9997`
⇒ 这些是**模型内部硬点**（供网格/铰链/变形用），不参与零件装配。

## 3. 判据：怎么判断「这个槽有没有几何」

**看声明类的 `configureType` 调用数**，不是看类名：

| 类别 | `configureType` 调用 | 例 |
|---|---|---|
| 有几何 | **≥ 1 且必有 `slot`** | `F_Bumper_stock`：`lods/flags/use_mesh/lod/dirt_texture/body×6/bone/noclick×6/nocollision/slot/wing×3/damage` |
| 有几何（无 `use_mesh`） | 仍有 `lods/lod/bone/damage/flexible` | `Rim_F_ST_stock`：`lods×2/lod/bone/damage/slot×5`（网格由 `lods`+类名隐含） |
| **纯参数件** | **0** | `IEngine_stage_II`、`IRunningGear_stage_II`、`INitrous_stage_II`、`ICTF_Lightbar` |

- 691 个声明槽的类里，**0 个**是「只有 `slot` 没有别的 `configureType`」⇒ 有 `slot` 就必有外观配置。
- 1193 个类 `configureType` 调用数为 **0** ⇒ 它们带来的零件**只改数值，不产生网格**。

## 5. 有声明但位姿为零的 20 个槽

`100, 101-104, 131-134, 911, 912, 1020, 1021, 2120, 2220, 3140, 3141, 3240, 3241, 9999`

它们**确有声明**（存在该行）但 pos = `0.000 0.000 0.000` ⇒ 位置来自别的系统：

- **轮毂/轮胎（100 / 3140,3141,3240,3241）**：位置由**物理轮数组**给（`docs/44 §2.1`：`[车+0x20a4]`，步长 `0x1528`；轮序 FL,FR,RL,RR 见 `docs/55 §6.1`）。
- **骨架 `101-104/131-134/911/912`**：模型硬点，随车体网格走。
- **`9999`（减重）**：故意零位，零件不产生外观（`docs/55 §6` 槽 9999 同款）。
- **`2120`（方向盘）/`2220`（内饰）**：由零件类自带网格直接落在车内原位。

## 6. 重制侧规则

1. **`geometry`（46 槽）**：装配时把零件网格放到该 (pos, rot)。**同一 item 槽的不同 `style_*` 可以位姿不同**（换件即换位）。
2. **`zero_pose`（20 槽）**：不要用槽位姿定位；轮位走物理轮数组，骨架随车体。
3. **`logical`（12 槽）**：只走 stats 通道（`docs/55 §2`），**不做可视化插槽**。
4. **`dead`（19 槽）**：可忽略；但 **id 必须保留**（`ITEMSLOT_*` 枚举顺序与 `slotLookupTable` 下标绑定，删了会错位）。
