> 方法：全 `.text` 扫 `B9 <imm32>`（= `mov ecx, imm`）+ 紧随的 `E8/E9 rel32`（call/jmp），过滤 `imm ∈ [0x740000,0x790000)`（`.data`/`.bss`）。

> 证据等级：**实测**（地址与目标均机械抽取）。

## 2. 用法要点

* **`mov ecx, <全局>; call <方法>` ⇒ 该全局是 `this`**：这是判断某类为单例的决定性证据，强于「它出现在 `.data`」。
* **桩区（`0x6E4xxx`–`0x6E6xxx`）成对的 `call ctor` / `jmp dtor`** 给出全局对象的生命周期函数；只有析构桩而没有构造桩者，说明由 CRT 静态零初始化（POD）。
* **`0x779F20`（物理世界）的方法集即物理 API**：`0x4B16A0` / `0x4B1740` / `0x4B2350` / `0x4B2B90`(step) / `0x4B2DA0` / `0x4B2E70` / `0x4B7900` / `0x4B7990` / `0x4B7F90` / `0x4B81C0`(建体) / `0x4B2FE0`(ctor) / `0x4B2B70`(dtor)。
* ★ **`0x779F20` 的 `ctor` 站点里有 `0x426242` 与 `0x4263BD`** —— 正是 `PhysicsRef.createSphere/createBox` 的内部地址 ⇒ **`PhysicsRef` 系列 API 就是在全局世界对象上调用方法** ✓
* ★★★ **`0x781E80`（816 个站点，ctor `0x5026D0`、dtor `0x503B60`）= 渲染器/设备管理器单例**（已读 ctor 确认）：
  * `+0x90/+0x92/+0x94` = **word 宽/高/位深**，ctor 写入 **640 / 480 / 16**（默认视频模式）
  * ctor 调 `call [0x6E71C4]`（= **`KERNEL32!GetModuleHandleA`**，实参 `push 0`）
    ⇒ 返回值存入 **`0x781DC8` = 本进程的 `hInstance`**（★ **不是设备指针**，纠正早期猜测）
  * `+0xE48` / `+0xE54` = 两个内嵌子对象（`0x44C620` 初始化）；`+0xC/+0x108/+0x300/+0xF38` = 1.0（标量默认）
  * 对象尺寸 > `0x1040`（ctor 触到 `+0x1040`）⇒ 巨型单例
  * 与 `docs/26` 的「设备指针 `0x781E04`」同在 `0x781Exx` 区；**816 个站点 = 每次绘制都命中**
* ★ 相关：**`docs/47` 导入表**（新建）—— `d3d9.dll` 只导入 `Direct3DCreate9`，其余走 COM 虚表；
  `d3dx9_30.dll` 39 个函数中含 `D3DXVec3Transform`/`D3DXMatrixMultiply`/`D3DXMatrixInverse`
  ⇒ **这些是 inline 的，会被内联进调用者**，项目里多处「M·v+t 仿射形状」应优先归为内联 D3DX 数学。
* ★ **`0x771050`（200 站点，ctor `0x434F10`、dtor `0x435140`）**：方法族集中在 `0x433xxx–0x436xxx`，
  是另一个高频全局服务对象（待定名）。
* 与 `docs/44` §12.4 的物理单例表（`0x8DF990`/`0x8DF6E8`/`0x8DF820`）互为补充。
