## 3. 顶点记录格式（已确证）

**44 字节定长**：

| 偏移 | 类型 | 内容 |
|---|---|---|
| `+0` | `f32` | u |
| `+4` | `f32` | v |
| `+8` | `f32` | c1（96–97% 落在 [0,1]，疑似第二套 UV / 光照图坐标） |
| `+12` | `f32` | c2 |
| `+16` | `f32` ×3 | **位置** |
| `+28` | `f32` ×3 | **法线** |
| `+40` | `u32` | 打包颜色（实测普遍为 `0xffffffff` = 白色 RGBA） |

### 判定依据

* **`+40` 在全部 48,719 条记录中都是 `0xffffffff`** —— 第一眼我误判为「分隔符」，
  实际是**白色顶点色**（与 INVO 的 `+24` 颜色字段同理）。这点纠正后整个结构才对上。
* **48,428 / 48,719 条记录的法线长度精确等于 1.000**（`|n| = 1.000`）。
  这个不变量直接钉死 `+28` 的偏移。
* 位置包围盒 `x[-6088, 9926] y[-1, 1162] z[-8031, 2433]` ——
  y 是高度（0–1162），水平范围 ±8 km，符合赛道尺度。
* 顶点记录段 **149 段连续**，每段内部严格 44 字节步长，段长 ≤ 58,596 B。

## 4. 索引段（拓扑已连通）

顶点段之后紧接 `[若干字节头][u16 索引列表]`：

* **`0xFFFF` 是三角形 strip 的重启标记**，不是真实索引 —— 必须排除后再做上界检查。
* 实测到的索引段头长度：`16`(×39)、`24`(×27)、`48`(×5)、`0`(×2)。
* ✅ **决定性验证**：`max(index) < vertexCount`，且模式是标准 strip：
  ```
  0,1,2, 1,3,2, 4,5,6, 5,7,6, 8,...
  ```
  （第一个子网格：1024 个索引 / 341 三角形，`max = 725 < 727` 顶点）

### 目视验证

`tools/coastline_index.py` 导出 OBJ 并渲染（软光栅器）：
俯视图呈现**完整的海岸线公路网**（蜿蜒主路 + 大环 + 建筑群），
侧视图显示平坦地形起伏 —— **不是噪声，是连通曲面**。

## 5. 成果与工具

| 项 | 数值 |
|---|---|
| 真实顶点数组（≥3 个有效顶点） | **99** |
| 有效顶点 | **53,916** |
| 成功配对的顶点数组 | **74 / 99** |
| 索引列表 | **221**（均 **3.0** 条/子网格） |
| 已配对顶点 | **53,466 = 99.17%** |
| 未配对顶点 | 450（**0.83%**，25 段，多为 3–6 顶点） |
| 导出三角形 | **28,878** |

> **v1 的「73/148 未配对」是我自己的误判。** 那 149 个「顶点数组」里有 **76 个是碎片**
> （只含 0–4 个顶点，只是恰好出现了 `0xffffffff` 这个词）。
> 过滤掉碎片后真实数组是 99 个，其中 **74 个成功配对**，
> 未配对的 25 段合计只有 450 个顶点。
> 同时把「每块只取一条索引列表」改成**循环扫描块内全部列表**后，
> 列表数从 70 升到 **221**，三角形从 24,433 升到 **28,878**。

### 为什么是 74 而不是 99

剩下 25 段太小（3–6 个顶点），它们的索引列表位于 855 KB 的区域内，
在这么低的上界（`max < 6`）下任何浮点数据都能伪装成合法索引，无法可靠区分 ——
**这是可靠性的边界，不是格式没解对**。

### 仍无法解释的部分（诚实记录）

blob 里只有 **21.4%** 的字节属于 44 字节顶点记录，剩下 **~8.7 MB 仍未归类**。
已验证这不是「法线不够精确」导致的漏检：

| 法线长度窗口 | 命中率 |
|---|---|
| `\|n\|² ∈ [0.998, 1.002]`（精确单位） | 2.1% |
| `\|n\|² ∈ [0.95, 1.05]` | 2.4% |
| `\|n\|² ∈ [0.5, 2.0]` | 5.7% |

放宽窗口几乎没有增加命中 → **剩下的 78% 确实不是顶点记录**，
而是另一类数据（u16 索引为主，见 `0,0,1` 模式以 **44 字节**为间隔出现 217 次）。

| 工具 | 作用 |
|---|---|
| `tools/gap_owner.py` | 定位 gap 所属容器并 dump 头部 |
| `tools/coastline_probe.py` | 哨兵间距 / 单位浮点三元组 / 逐字段统计 |
| `tools/coastline_mesh.py` | 顶点提取 + 点云渲染 + OBJ |
| `tools/coastline_index.py` | 索引解析 + 三角形导出 + 渲染 |

## 6. 仍缺

* **75 / 148 顶点段未配对**：索引列表在块内有多条，目前只取每块第一条
  （需按「列表结束即下一列表开始」循环扫描）。
* **索引段头语义未定**（0 / 16 / 24 / 48 字节）：可能是包围盒 / 材质参数 / LOD 阈值。
* **剩余 ~8.6 MB 未归类**：blob 里还有顶点色不是白色的子网格，
  靠「找 `0xffffffff`」的段检测漏掉了它们 —— 应改为靠**索引 ramp 定位**再回推顶点段。
* **`c1`/`c2` 两个字段**：96–97% 在 [0,1]，疑似第二套 UV，未证实。
* `hills` 的位打包流（3.1 MB）与 ~29 MB 场景实例数据仍未解。
