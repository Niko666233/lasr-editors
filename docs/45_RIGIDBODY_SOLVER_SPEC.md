## 1. 一句话架构

**不是**「质点 + 显式欧拉」模型，而是 **刚体 + 约束行求解 + Baumgarte 速度投影**：

```
应用层施力 → facc(+0x108) 累加
              ↓
   碰撞器生成接触对 → 回调 0x6B1B50
              ├ 重力 f += m·g
              ├ 逐约束类型行内核（读 facc + 现速度 + 限幅）→ 逐体修正量 Δ（6 分量）
              ├ Phase1 聚合 Δ → 连续缓冲（带矩阵批量变换）
              └ Phase2 ★ lvel/avel += Δ / dt     ← 力的最终落地点
```

**力的消费点 = `0x6B1B50` 的 Phase 2（`0x6B2BB2`–`0x6B2C3E`）**，缩放因子 `k = 1.0/dt`（实测三跳传参链，见 §6.5）。

## 2. 每帧管线（实测，逐跳地址）

```
游戏帧
└ 0x5F9020                     顶层物理/载具系统更新
   └ 0x435DE0 / 0x4360B0
      └ 0x4B2B90               ★ 世界 step 入口（SEH 帧；= 世界对象虚表 +0x2C）
         ├ 0x4B79A0(world, dt) ★ 时间推进：dt 累加，下限 epsilon 0x6EBF8C = 1e-4
         ├ 遍历 world+0x240 体链表（逐体虚调用；[obj+0x24] id → [0x7439B0+id*4] 子对象偏移表）
         ├ 0x6802B0(space, dt, cb1, cb2)   ★ 碰撞
         │    └ 0x69A000(space, dt, 0x6B1B50, …)   ★ 接触生成 + 回调分发
         │         └ ★★★ 0x6B1B50(space, 体数组, 体数, …, 行数, dt)
         │              = 接触/约束求解回调（本规格核心，5760 B）
         ├ 0x681300(world, space, cb1=0x4B23F0, cb2=0x4B2A90)  = vtable[0x2C] 求解跳板
         ├ 0x4B3920 收尾
         ├ 0x4B98D0(world)        引擎 → 游戏状态同步
         └ 0x69A3D0(space, 0x4DA7A0, 0x4B2340, 0x4B2340)       帧后清理
```

**时间步**：非固定子步。每帧推进一次，`dt = 帧时长 + 残留`，仅受下限 `[0x6EBF8C] = 1e-4` 保护。
**dt 的通道**：`dt` **不是全局量**，而是 **碰撞调用的实参**：
`0x6802B0` 把 `dt` 写进 `space+0x68`（`0x6802CF`）并随参数传给 `0x69A000` → 再传给回调 `0x6B1B50` 的 `arg6`。

## 4. 刚体（引擎体）布局

**本体 = `0x174`（372）字节的 POD 结构，无虚表**（实测：ctor `0x6803B0` 以 `push 0x174; call 0x69b9c0` 分配；
`[+0x00]` = 属主指针，不是 vtable）。ctor 内：`+0xB8` ← 单位矩阵（`0x682A60`），
`+0x64`(0xC 字节) / `+0xA8` / `+0xE8` / `+0xF8` / `+0x108` / `+0x118` 清零（`0x69B1C0` 零填充），
`+0xE8/F8/108/118` 各 4 字节 ⇒ 与下表一致。

> ⚠ 早期把 `0x735454` 称为"刚体虚表"**需修正**：该表成员操作的对象**布局相同但不是刚体本身**（POD 无虚表）。
> 规范槽号（表 `0x735454`）：**#12 = `0x682490`**（x87 力写点）、**#15 = `0x681980`**（逐体虚调用）、`#11 = 0x681900`。


**实测 + 两源交叉**（ctor `0x681520` 缓存指针 / 序列化 `0x44F350` / 积分器 `0x6B1B50` / 力 API `0x680810`）：

| 偏移 | 含义 | 证据 |

## 6. 求解器（本规格的核心）

### 6.1 交互回调注册表（引擎初始化 `0x67E2D7`–`0x67E350`）

| 全局 | 回调 | 作用 |
|---|---|---|
| `[0x8DE7E8]` | **`0x6A1B20`** | 单对接触/约束求解 |
| `[0x8DE818]` | **`0x6A4410`** | 驱动 `SolveConstraint` |
| `[0x8DE7E0]` | `0x69C130` | 含取位置 |

**全局物理单例**（MSVC 静态初始化桩 `0x6E5860`/`0x6E6700`）：
`0x8DF990`（虚表 **`0x73581C`**，ctor `0x6C0F40`，dtor `0x6C0FB0`，构造时注入碰撞近邻回调 `0x4DA7A0`
+ 内嵌「3 × 12 字节」图元数组于 `+0x10C`，标志字节 `+0x130`）· `0x8DF6E8`（ctor `0x6C6F00`）·
`0x8DF820`（ctor `0x6B7830`）。`[0x8DF994]` = 标志字 · `0x8DF938` = 全局约束描述符 · `0x8DF9A0` = 结果指针。

### 6.2 单对求解 `0x6A1B20`

`sub esp,0x218`（**536 字节栈工作区**）；`0x6A0460` 把两体姿态/位置缓存进工作区
（`+0x200/+0x204` = 两体指针；`+0x00..0x28` B 体矩阵；`+0x30` B 体位置；`+0xD8` A 体矩阵；`+0x108` A 体位置）；
x87 点积 + `fabs` 与 **`[0x6E7DEC] = 0.9`** 比较（接近性判据，分离则跳过）；再调 **`0x6A0E70`** 组装求解。

> ⚠ 该工作区的 `+0x108` 是**对手体位置**，不是 facc（同偏移撞车，docs/44 §11.16）。

### 6.3 `SolveConstraint` `0x6C69B0` → 8 个行内核

```asm
0x6c69b2  edi = arg(约束描述符) ; esi = ecx = this（全局单例 0x8DF990）
0x6c69ef  call 0x6C1010                 ; 准备
0x6c69fc  eax = [edi+8]                 ; 约束类型位
0x6c69ff  edi = [edi+0x10]              ; 子描述符（含 6 float 参数块 [edi..edi+0x14]）
0x6c6a41  test byte [esi+4], 0x10       ; 标志位二分
0x6c6a4d… call 0x6C61B0 / 0x6C5470 / 0x6C4CD0 / 0x6C3FC0 / 0x6C1C40 / 0x6C2650 / 0x6C2DC0 / 0x6C3810
```

**8 个行内核**（等距同源，每个恰好一条 `facc` 访问且字节相同 `F3 0F 58 86 08 01 00 00`）：

| 内核 | `addss xmm0,[esi+0x108]` 处 | | 内核 | 处 |
|---|---|---|---|---|
| `0x6C1C40` | `0x6C21B2` | | `0x6C3FC0` | `0x6C4531` |
| `0x6C2650` | `0x6C2BC0` | | `0x6C4CD0` | `0x6C5242` |
| `0x6C2DC0` | `0x6C3374` | | `0x6C5470` | `0x6C5A22` |
| `0x6C3810` | `0x6C3DC1` | | `0x6C61B0` | `0x6C6763` |

内核形状（`0x6C1C40` 为例）：
```asm
0x6c1eb0  xmm4 = [edi+0x14] · [esi+0x38]
0x6c1ec0  xmm3 = [edi+0x10] · [esi+0x3c]
0x6c1ec9  addss xmm3, xmm4
0x6c1ecd  addss xmm3, [esi+0xE8]        ; ★ 加上当前速度
0x6c1edf  and eax, 0x7fffffff ; cmp eax, ecx ; ja 0x6C263A   ; ★ |v| 与限值比较 → 超限分支
…
0x6c21b2  addss xmm0, [esi+0x108]       ; ★ 力累加器进表达式
0x6c21b2  … 之后 fabs/faddp 一串绝对值求和 + 限幅
```
⇒ 内核 = **逐约束类型的「速度/行量更新 + 限幅」器**（读 facc + 读现速度 + 夹取）。
⚠ 内核的 `esi` 是**全局单例 `0x8DF990`**（`mov ecx,0x8DF990` 四处调用点），
而 `0x6B1B50` 的 `[esi+0x108]` 是**真刚体**（同块有 `+0xE8` 速度、`+0x20` 质量）。二者需分开归档。

### 6.4 Phase 1：聚合 + 批量变换（`0x6B2AC8`–`0x6B2B40`）

```asm
0x6b2ac8  ecx = [ecx + eax*8]      ; 该体的行计数（记录步长 8 字节）
0x6b2ad3  shl ecx, 2               ; ×4 ⇒ 字节数
0x6b2ade  esi += 0x38              ; ★ 源块 = 记录 +0x38
0x6b2ae1  rep movsd / rep movsb    ; ★★ 逐体把 N×4 字节拷进连续缓冲
0x6b2b04  call 0x667600            ; 对齐/分配辅助
0x6b2b14  edx = [ebp+8] + 0x58     ; ★ arg1+0x58 = 矩阵
0x6b2b17… push 一长串参数（矩阵 + 两组计数 + 缓冲）→ 批量变换
```

### 6.5 ★★★ Phase 2：Baumgarte 速度投影（`0x6B2BB2`–`0x6B2C3E`）

```asm
0x6b2ba9  edx = [ebp+0xc]             ; 体指针数组
0x6b2baf  ecx = ebx + 8               ; 逐体修正量缓冲
0x6b2bb2  esi = [edx + eax*4]         ; 第 i 个刚体
0x6b2bb5  xmm1 = [ecx - 8]            ; Δx
0x6b2bbf  mulss xmm1, xmm0            ; × k
0x6b2bc3  addss xmm1, [esi + 0xE8]    ; ★★★ lvel.x += Δx·k
0x6b2bcb  movss [esi + 0xE8], xmm1
0x6b2bdf  addss xmm1, [esi + 0xEC] ; [esi+0xEC] = xmm1   ; lvel.y
0x6b2bfa  addss xmm1, [esi + 0xF0] ; [esi+0xF0] = xmm1   ; lvel.z
0x6b2c16  addss xmm1, [esi + 0xF8] ; [esi+0xF8] = xmm1   ; avel.x
0x6b2c32  addss xmm1, [esi + 0xFC] ; [esi+0xFC] = xmm1   ; avel.y
0x6b2c3e  …                                               ; avel.z (+0x100)
0x6b2c57  add ecx, 0x18               ; ★ 缓冲步长 = 6 float
```

**缩放因子**（`0x6B1B56`）：
```asm
xmm0 = [0x6E766C]        ; = 1.0（实测 f32(0x6E766C) = 1.0）
xmm0 /= [ebp + 0x1c]     ; ★ k = 1.0 / arg6
```

**`arg6` 的传参链（三跳实测）**：
```
0x6802B0(space, dt, cb1, cb2)            ; arg2 = dt（float，0x6802BC 读 [esp+8]）
  └ 0x69A000(space, dt, 0x6B1B50, …)     ; 0x69A000 的 [ebp+0xc] = arg2 = dt
       └ 回调 0x6B1B50 的第 6 个实参 = [ebp+0xc]（0x69A292 call [ebp+0x10]，0x18 字节实参）
```
⇒ **`arg6 = dt`，`k = 1/dt`，Phase 2 = `lvel/avel += Δ / dt`** ——
经典的 **Baumgarte 式「位置修正 → 速度投影」**（等价于 `v += β·C/dt`，β 已折进 Δ）。

**重制实现建议**：
```
每帧（每体 6 分量）：
    1. 力阶段：facc += ΣF_app + m·g           // §5
    2. 行求解：对每个接触/约束行 → Δ（3 线 + 3 角，含限幅）   // §6.3
    3. 聚合 + 变换：Δ 从各体 [记录+0x38] 汇入缓冲 → 矩阵变换   // §6.4
    4. 投影：lvel += Δ_lin/dt ; avel += Δ_ang/dt              // §6.5
    5. 位姿：由 lvel/avel 更新矩阵 +0xB8（平移列 +0xC4/+0xD4/+0xE4）
```
### 6.7 位姿从哪来（已回答，实测调用链）

```
0x46E770  车的每帧主方法（虚表槽 #45）
  └ 0x45C680   ★「状态推送」—— 唯一调用点 0x46EC02
       ├ 0x67F470([车+0x2A0], 姿态)      ; setPose
       ├ 0x67F500([车+0x2A0], v)         ; setLinearVelocity
       ├ 0x67F530([车+0x2A0], ω)         ; setAngularVelocity
       └ [车+0x2A4] → 0x67FC90 / 0x67FFB0 / 0x67FFA0   ; 次刚体/几何体
```
**⇒ 位姿由游戏侧（车代码）算出后推送进引擎；引擎本体不含「读速度→写位姿」的积分。**

**穷尽佐证**：`getLinearVelocity`（`0x67F590`，返回 `this+0xE8`）**全库仅 4 个调用者** ——
`0x45C680`（推送器）、`0x469FE0`（车每帧主方法）、`0x475560`（**状态拷贝/同步**：拷 48B 矩阵后
`setPose`+`setLinearVelocity`+`setAngularVelocity`，**无 dt 参与**）、`0x4BA250`（应用层 getter 包装）。
**无一为积分器。**

**刚体 getter API 全表（机械扫出）**：`0x67F570`→`+0xB8`(矩阵) · `0x67F590`→`+0xE8`(线速度) ·
`0x67F5A0`→`+0xF8`(角速度) · `0x67F7B0`→`+0x108`(力) · `0x67F7C0`→`+0x118`(扭矩) ·
`0x67F560`→`+0x98` · `0x67F580`→`+0xA8`。

**新锚点（应用层 ↔ 引擎）**：`[车对象+0x2A0]` = **主刚体句柄**；`[车对象+0x2A4]` = **次刚体句柄**。

**第 5 步的补充说明**：穷尽搜索的结论：本二进制中**不存在**"读刚体 `lvel` → 写刚体位姿"的函数
（真·读 lvel 的 30 个函数 ∩ 写矩阵平移列 = 0；曾疑为积分器的 `0x6B84D0`/`0x6BB550` 实为**扫掠/运动查询驱动**，
把 `&lvel` 传给 `0x6B7090`；`0x4B1260`/`0x44D810`/`0x4BDC30`/`0x6898F0` 均为初始化/重置/姿态设置器）。
⇒ **推断：引擎只算速度，位姿由外部（游戏侧）积分后经 `0x67F470` 族提交** —— 与 LASR「车辆物理在游戏侧」一致。
**重制含义**：速度层按 §6 复刻；位姿层可直接用主流的 `pose = integrate(pose, lvel·dt)`，无需迁就原生实现。
