# 34 · 音频音高公式（原生侧实证）

> 本文给出**全游戏唯一**的音高设置点的完整公式。查法：先给 FF 25 桩梯命名，
> 再用"谁调用 `setFrequency`"反查调用点 —— 全镜像只有一个。

## 1. FMOD 导入桩梯（`0x6299a0` 起，已全部命名）

`tools/ff25_stubs.py --stub <地址>` 可直接反查。这段梯子每级 6 字节（`FF 25 <IAT>`），
IAT 槽逐 4 字节递减：

| 桩地址 | IAT 槽 | 导入函数 |
|---|---|---|
| `0x6299a0` | `0x6e74d4` | `setPriority(Channel, int)` |
| **`0x6299a6`** | `0x6e74d0` | ★ **`setFrequency(Channel, float)`** |
| **`0x6299ac`** | `0x6e74cc` | ★ **`getDefaults(Sound, float*, float*, int*)`** |
| `0x6299b2` | `0x6e74c8` | `setVolume(Channel, float)` |
| `0x6299b8` | `0x6e74c4` | `set3DConeOrientation(Channel, FMOD_VECTOR*)` |
| `0x6299be` | `0x6e74c0` | `set3DAttributes(Channel, FMOD_VECTOR*, FMOD_VECTOR*)` |
| `0x6299c4` | `0x6e74bc` | `setPan(Channel, float)` |
| `0x6299ca` | `0x6e74b8` | `getMode(Channel, uint*)` |
| `0x6299d0` | `0x6e74b4` | `getOutput(System, FMOD_OUTPUTTYPE*)` |

## 2. ★ 音高函数（`0x564319`–`0x564379`，全游戏唯一）

```asm
0x564319  lea edx,[esp+0x1c] / push edx / push eax
0x564322  call getDefaults            ; ★ 读该 Sound 的 deffreq / defvol / defpan
                                        ;   （正是 FSB3 头里的同名字段）
0x564327  fld  qword [0x6ea580] = 0.0  ; 阈值
0x56432d  fld  dword [esi+0x28]        ; ★ 该对象的基准音高
0x564330  fcompi / fstp / jbe 0x564349
          ; ── 分支 A：基准 > 0 ──
0x564336  movss xmm0,[esi+0x28] / mulss xmm0,[esp+0x10]   ; ★ freq = 基准 × 输入
0x564347  jmp 0x564373
          ; ── 分支 B：基准为 0 或负 ──
0x564349  call 0x6674f8                ; rand()
0x56434e  and  eax, 0x0FFF             ; → 0..4095
0x564359  fild dword [esp+0x1c]
0x56435d  jge 0x564365
0x56435f  fadd dword [0x6e8b08]        ; ★ = 4294967296.0 = 2^32
                                        ;   （无符号整数 → float 的标准偏置；
                                        ;    实测值恒在 0..4095 ⇒ 该修正永不触发）
0x564365  fadd dword [esp+0x10]        ; += 输入
0x564369  fsub dword [0x6f5d30]        ; ★ −= 2048.0
0x56436f  fstp dword [esp+0x10]
          ; ── 收尾 ──
0x564373  mov ecx,[esp+0x10] / push ecx / push edi        ; (通道, 频率)
0x564379  call setFrequency
```

### 2.1 等价 C 代码

```c
float f;
int   v;                                   // 假定来自 FSB3 头的默认值区
getDefaults(sound, &f_dummy, &f_dummy2, &v);   // 参数排布按 FMOD 原型

if (obj->basefreq > 0.0f)
    freq = obj->basefreq * input;                        // 正常：基准 × 输入
else
    freq = input + (float)(rand() & 0xFFF) - 2048.0f;    // 退化：±2048 Hz 随机
setFrequency(obj->channel, freq);
```

### 2.2 常量（已读实值）

| 地址 | 值 | 作用 |
|---|---|---|
| `0x6ea580` | **0.0** | 分支阈值 |
| `0x6e8b08` | **4294967296.0 (2³²)** | 无符号→float 偏置（死代码，恒不触发） |
| `0x6f5d30` | **2048.0** | 随机偏移中心 ⇒ 波动范围 **±2048** |

⇒ ★ **随机抖动 = `rand() & 0xFFF − 2048`，即 ±2048**，与 FSB3 头里的 `varfreq`
字段配套使用（该字段已逐条导出到 `out_fsb.csv`）。

## 3. 包装类区域结构（`0x5642a0`–`0x564460`）

| 地址 | 内容 |
|---|---|
| `0x564230` / `0x564240` / `0x564270` | **句柄校验入口**：`mov eax,[ecx]; test eax,eax; (≤0 → ret)`，随后 `dec eax` 并转 `0x56f760` / `0x56f7e0` ⇒ 1-based 句柄 → 内部对象 |
| `0x5642c8` | 一个方法的 `ret 4` 结束 |
| `0x5642d0`+ | **3D/声像属性刷新方法**：依次调 `getMode`(0x6299ca) → 分支 → `setPan`(0x6299c4) / `set3DAttributes`(0x6299be) / `set3DConeOrientation`(0x6299b8) 等 |
| `0x5643d3`–`0x5643d9` | ★ **4 路 switch 分派**：`cmp eax,3 / ja … / jmp dword [eax*4 + 0x564438]` |
| `0x564438` | ★ **跳转表**：`0x5643d7`, `0x5643ec`, `0x56440a`, `0x56441d`（表后为 `0xcc` 填充） |
| `0x5642a0`–`0x564460` | 上述所有方法的整体区域，**只有跳转表一处指针引用** |

## 4. ✅ 已闭合（2026-09-28 动态实证）

用 `tools/pinch_caller.py` 在 `0x564319` 上挂**一条**执行断点，命中时 `[esp]` 是
push 进去的对象成员地址（`esi+0x58`）⇒ 该地址**不是函数入口**，返回地址在栈更深处。
工具自动把栈窗口里所有"`v-5` 处是 `E8`"的项挑出来，得到三级调用链：

```
0x40f2b2  call 0x42f0d0
0x42f3a2  call 0x5648b0          ← startSoundFX（__thiscall，6 参数，ret 0x18）
0x56494d  call 0x564280
          0x564280 → 0x564319     ← ★ 全游戏唯一音高点
```

### 4.1 音高输入的来源（`0x42f378`–`0x42f3a2`）

```asm
0x42f378  mov edx,[esp+0x10]        ; 参数对象
0x42f37c  mov eax,[edx+8]
0x42f383  mov eax,[eax+0x28]        ; ★★ 音高参数 = [[params+8]+0x28]（两级解引用）
0x42f38a  push 0 / push 0
0x42f38e  push 0x763dcc             ; 参数模板（见 §4.3）
0x42f393  push eax                  ; ← 音高值
0x42f394  push edi
0x42f397  call 0x42b230             ; "取 [ecx+0x10]→[..+0x58]"：类型 7（音频发信体）的通道
0x42f39c  push eax                  ; ← 通道句柄
0x42f39d  mov ecx, 0x897380         ; ★★ SoundManager 单例
0x42f3a2  call 0x5648b0
```

`0x42b230`：
```asm
cmp [ecx+0xC], 7 / jne / mov eax,[ecx+0x10] / test / mov eax,[eax+0x58] / ret
```

### 4.2 ★ SoundEntry 数组（引擎级音频对象表）

```asm
0x564907  imul eax, eax, 0x64       ; sizeof(SoundEntry) = 100
0x56490a  add  eax, 0x890e70        ; ★ 数组基址
0x5648d6  mov  ecx, 0x890e80        ; 基址 +0x10 = 第一个 entry 的状态字段
0x5648e0  cmp  [ecx], 0 / je …      ; [entry+0x10] == 0 ⇒ 空闲
0x5648e5  add  ecx, 0x64            ; 步进 100 字节
0x5648e9  cmp  ecx, 0x897280 / jl
0x5648f1  push 0x6f5d54 → "Can't start soundFX: SoundEntry array is full"
```

| 量 | 值 |
|---|---|
| 数组基址 | **`0x890E70`** |
| 条目大小 | **100 (`0x64`) 字节** |
| 容量 | **256 条**（`(0x897280 − 0x890E80) / 0x64`，逐字节核对：`0x890E70 + 0x6400` 的 `+0x10` 正好 `0x897280`） |
| 状态字段 | **`+0x10`**（0 = 空闲，1 = 已启动 —— 与 `0x56492b` 的 `mov [eax+0x10],1` 两处独立互证） |
| 溢出行为 | 打印 `"Can't start soundFX: SoundEntry array is full"` 后返回 **0**（`0x564901 xor eax,eax`） |

条目字段（`0x564913`–`0x56494a` 写入，部分）：`+0x04` 参数、`+0x08` 初值 0、
`+0x10` 状态、`+0x14`/`+0x18` 两个指针、**`+0x1C`–`+0x58` 由 `rep movsd 0xf` 从调用者
结构体拷入的 60 字节参数块**、`+0x58` 初值 **1.0f**、`+0x5C` 参数。

### 4.3 `0x763dcc` / `0x763e08`

两者相差正好 `0x3C`（60 字节 = 上面拷入的块长），且 **文件里不在任何节内**
⇒ 位于 `.data` 的零初始化段，**运行时才被填写** ⇒ 读取须在运行时 `ReadProcessMemory`。

> **保留：当初的静态穷尽记录**（这一节的问题当初按纯静态判为"未闭合"，
> 下方表格是当时的搜索空间，留作方法记录 —— 结论已被上文取代。）


**"输入"从哪来（= 负载→选层 / RPM→音高 的上游）仍未找到** ✗。已穷尽的搜索：

| 搜索 | 结果 |
|---|---|
| `E8` 目标落在 `[0x5642a0, 0x56431a)` | **0 个** ✗ |
| `E8` 目标落在 `[0x564200, 0x56431a)` | 仅 `0x564230/40/270`（**本区域内**的入口）✗ |
| 4 字节字存有 `[0x564280, 0x564460)` 的地址 | 仅**跳转表自身**（`0x564438` 那 4 项）✗ |
| 引用 `0x564438` | 仅 `0x5643d3` 的 `jmp [eax*4+0x564438]` ✗ |
| `0x415xxx–0x419xxx` 的调用者 | 是**对象生命周期/析构**路径（`memmove` + `ret 4` + 句柄判零），不是每帧更新 ✗ |

⇒ 结论：该函数**不是**通过 `E8`、也不是通过虚表指针被调用的，大概率经由
**4 路 switch 的内部分派**（其 switch 值来源未定），或由**运行时解析出来的函数指针**
调用 —— 旁证：`0x6307b0` 处有一段 `f(handle, 0x18)` 式的**按序号动态解析导出**代码，
随后 `cmp eax, 0x564342`（`0x564342` 正是该函数内的一个 case 入口）⇒ ★ **FMOD 是运行时
按序号解析的**，这也解释了为什么 `nplay` 等原生方法名**不在** `out_native_methods.csv` 里。

### 下一轮的两条确定性路径

1. **动态**（最省事、100% 确定）：在 `0x564319` 或 `0x564342` 上下执行断点，**读返回地址**
   ⇒ 直接得到调用者。工具已就绪：`tools/attach_trace.py`（attach 到已运行的游戏、
   遵守 7 条安全铁律、退出前先清断点再分离），用户只需把游戏开起来（**需要用户花 1 分钟**）。
2. **静态**：读 4 路 switch 的 switch 值来源 + `0x6307b0` 那段动态解析的表（哪张表、
   哪个序号对应 `0x564342`）⇒ 反推该函数的注册名与调用时机。

## 5. ★ 调用时机实测（"是每帧吗？"—— 不是）

用 `pinch_caller.py -n <N>`（计数模式：命中后清槽，等随后的 WX86 单步事件再挂回，
防自旋）在同一局游戏里跑了两轮：

| 轮次 | 窗口 | 命中 | 说明 |
|---|---|---|---|
| 1 | 30 s（单点模式，一击即收） | **1**（t = 12.79 s） | 抓到完整调用链（§4） |
| 2 | 30 s（计数模式，上限 25） | **0** | 同一局、同一地址、断点已确认挂上（`clear_dr` 预检 16/16 通过） |

⇒ ★ **该函数不是每帧调用**，而是**发声（start）事件驱动**。结合 §2 已证实的
"`setFrequency` 全镜像**只有一个**调用点"，得到结论：

> **引擎对一条 FMOD 通道只设置一次播放频率（在启动该声音时），之后从不再改。**

⇒ 因此**不存在"每帧音高公式"**。连续的音高变化只能由两种机制合成：

1. **分层采样 + 重启**：车辆音库每族 5 条（`idle` / `low|mid|high load` /
   `low|mid|high offload`，见 `docs/31`），换层＝**启动另一条声音**，而不是给旧声音改频率。
2. **启动时的随机抖动 ±2048 Hz**（§2.2）：正是为了让"反复重启"不出现机械感。

⇒ 重制时对应做法：**不做逐帧 `setFrequency`**，而是（a）按负载/RPM 切换层采样，
（b）在每次启动时给一个频率（基准×输入，或输入±2048 抖动），
（c）用 `SoundEntry` 数组（§4.2）管理并发声音、复用 256 个槽。

### 5.1 唯一还需一次实机确认的环节

若车辆在**行驶中**（转速连续变化）仍有音高滑动，那它必然来自**更频密的"重启"** ——
判据很简单：**让车在赛道上跑 30 秒并反复拉转速**，同时用
`pinch_caller.py <pid> 0x564319 30 -n 200` 数命中：

* 命中数**远大于**换层/换挡次数 ⇒ 存在高频重启路径（音高靠重启实现）；
* 命中数 ≈ 换层/换挡次数 ⇒ 本文结论完全成立，逐帧无频率写入。
