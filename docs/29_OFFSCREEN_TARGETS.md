# 29 · 离屏目标清单：阴影图 vs 每帧一次的离屏通道（静态实测）

> 本文的全部结论都来自**静态**阅读（`tools/at.py` / `tools/calls_to.py` /
> `tools/ff25_stubs.py`）+ **已在别处验证过的槽号锚点**。没有一次需要运行游戏。

## 0. 前置修正（本轮的关键工具 bug）

节表里的 `VirtualAddress` 是 **RVA**，必须加 `ImageBase` 才是运行时绝对地址。
我新写的两个工具漏了这一步，于是"任何目标都 0 匹配"、反汇编全是垃圾 —— 一度
被误读成"这些函数没有调用者"。修正后 `0x533180`（已知有调用者）立刻报出
2 个调用点 `0x53328c` / `0x5332c1`，与早先的通道顺序分析一致 ⇒ 工具可信。

## 1. FF 25 跳转桩索引（`tools/ff25_stubs.py`）

D3D/D3DX 的调用**不**走 `call [IAT]`（FF 15），而走导入跳转桩：`FF 25 <IAT>` 的桩 + `E8 桩`。
补上这一步后：**306 个导入函数 → 95 个跳转桩 → 228 个静态调用点**，全部可按名字检索。

独立复现的锚点（与此前结论一致，互为第二判据）：
- `d3d9.dll!Direct3DCreate9` ← **`0x502a85`**（早先静态定位相同 ✓）
- `d3dx9_30.dll!D3DXAssembleShader` ← `0x530414` / `0x530510`（与着色器容器分析一致 ✓）
- `d3dx9_30.dll!D3DXSHEvalHemisphereLight`（与 `docs/23` 的 SH 环境光一致 ✓）

## 2. 两个离屏目标，尺寸/格式都拿到了

### 2.1 每帧一次的离屏通道 —— **512×512**

`D3DXCreateTexture` 的调用点 `0x509097` / `0x5090b9`（**同一片代码**），参数完整可读：

```
push 0x200      ← 宽 = 512
push 0x200      ← 高 = 512
push 1          ← mip 层数 = 1
push 0          ← usage = 0
push 0x15       ← 格式 21 = D3DFMT_A8R8G8B8
lea eax,[esp+0x18] / push eax   ← &pTexture
push dword [0x781e04]           ← 设备（全局锚点）
call 0x5f91fc                   ← D3DXCreateTexture 桩
```

- **成对创建**（`0x509097` 与 `0x5090b9` 各建一张 512×512、格式相同的 ✓）
  ⇒ **ping-pong 双缓冲**，与早先在 DX8 档观测到的离屏目标交替（`0xd5bfe80`/`0xd5bfee0`）一致 ✓
- 同一片代码里还有 `call [edx+0x178]`。按**已验证**的槽号锚点顺推
  （65=SetTexture、67=SetTextureStageState、81/82=Draw*，均实测命中过）⇒ **槽 94 = 槽+0x178
  = `SetVertexShaderConstantF`**，即该通道会**往顶点着色器常量寄存器 7、8 上传矩阵**。
- 该通道每帧被 `0x504a20` 执行**恰好一次**（动态实测，见 `docs/28`）
- ★ **尺寸 512×512 ≠ 1664×1024** ⇒ **它不是阴影通道**，而是**动态反射/中间缓冲**。

### 2.2 阴影图 —— **1664×1024 × 2 张**

`push 0x680`（=1664）在 `.text` 里**只有 3 处**，全在 `0x4c1bxx–0x4c1cxx`：

```asm
0x4c1bd5 push 0x400        ; 1024
0x4c1bda push 0x680        ; 1664
0x4c1bfd call 0x53d960     ; ★ 创建函数
0x4c1c02 mov  [0x77a770], eax      ; ★ 句柄 A 存全局

0x4c1be8 push 0x400 / 0x4c1bf8 push 0x680 / call 0x53d960
0x4c1c02 → 0x77a770        ; 句柄 A
0x4c1bed mov  [0x77a774], eax ← 句柄 B（另一处同尺寸调用）
```

- **尺寸：1664×1024** ✓ —— 与 `docs/23` 的 `SHADOW_F` 一致，**这次有了真实创建点**
  （此前搜不到 1664，是因为它以 `push 0x680` 出现，且 `push` 形式与当时假设不同）
- **两张**（`0x77a770` / `0x77a774` 两个全局各自保存）
- **创建函数：`0x53d960`**（参数形态 `(宽, 高, 1, 档位)`）
- **同一段代码里有 `call 0x4ffb20`（参数 12 / 13 / 15）** —— 位于 `0x4ffxxx` 渲染器初始化区，
  形态是**能力/画质查询** ⇒ 影子系统按画质档选路径（与 `docs/25` 的三档渲染模式呼应）

## 3. 由此确定的事实（可进重制规格）

| 项 | 值 | 判据 |
|---|---|---|
| 阴影图尺寸 | **1664 × 1024** | `push 0x680`/`push 0x400` @ `0x4c1bd5`–`0x4c1c2f` ✓ |
| 阴影图数量 | **2** | 句柄写入 `0x77a770`、`0x77a774` ✓ |
| 阴影图创建函数 | **`0x53d960`** | 三处调用点 ✓ |
| 阴影档位查询 | `0x4ffb20`（参数 12/13/15） | `0x4c1bc2`/`0x4c1c17` 等 ✓ |
| 每帧一次的离屏通道 | **512×512 / A8R8G8B8 / 双缓冲** | `0x509097`、`0x5090b9` ✓ |
| 该通道的发起者 | `0x504a20`（每帧 1 次）+ 3 个调用点 | `docs/28` + `tools/calls_to.py` ✓ |
| 该通道会传 VS 常量 | 槽 94 = `SetVertexShaderConstantF` | 槽号锚点顺推 ✓ |
