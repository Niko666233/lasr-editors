## 0. 目标与判据

* 目标：在现代引擎（Unity / Unreal / Godot / Bevy）里**重制**，不是给原版做 mod。
* 优先级：**数值与规则 > 网格 > 贴图 > 音效 > 原生渲染细节**。
* 判据：每一步产出**可验证的产物**（工具输出 / 二进制地址 / 校验项），不接受「大概理解了」。

## 3. 下一步建议（按价值排序）

### ① 最小可玩竖向切片 —— 当前主任务

一条赛道 + 一台车 + 幽灵车 + 一局比赛规则，**只吃 `Assets/LASR/Data/*.json`**，直接在
`remaster/unity_project/` 里搭（引擎已定：**Unity 6.6 / 6000.6.x**）。

* 为什么：数据层已 80 项校验通过、交付包已导入自检通过，但**还没被真正的游戏逻辑消费过**。
  切片是第一个「玩法侧」可验证产物，会立刻暴露数据层的真缺口（坐标系 / 单位 / 字段歧义）。
* 起点：`docs/58`（包怎么用）+ `remaster/engine/mapping.md`（逐字段落到 Unity）+
  `Scripts/LasrTrackGizmos.cs`（用 `tracks.json` 把检查点/发车位/banner 直接摆进场景）。
* **进度：✅ 成立（2026-09-29）→ 全部实测、缺口与教训见 [`docs/59_SLICE.md`](59_SLICE.md)**。真实工程 `-batchmode` 实跑 **exit 0 / 33 项断言 0 ✗**：数据→场景一键生成（路面 ribbon + MeshCollider + 隐形护栏 + 检查点 + 发车位）、几何与真实幽灵录像逐点对上（起点线一致、检查点弧长最大差 0.13 m）、赛规纯逻辑 88/88 单测、无人值守跑完整圈 1610.3 m（4/4 检查点、`Lap=1`、`Finished`、无穿地/NaN）。
* **验收标准（做到这几条就算切片成立）**：
  1. 场景能一键从数据生成（`Tools ▸ LASR ▸ 切片 ▸ 构建场景`，或批处理入口），不手工摆东西；
  2. 车开得动：赛道由 `splines.json` 主线生成路面 + 碰撞体，车不穿地、不飞、不 NaN，能跑完一整圈；
  3. 规则生效：倒计时 → 起跑 → 按顺序过检查点 → 计圈/最佳圈 → 过线完赛（错序/重复不计），规则取自 `race_rules.json`；
  4. 幽灵车跑起来：吃 `Data/sample_ghost_*.json`，与现实录制同帧；
  5. 批处理自检可复现：构建场景 + 进 Play 模式自动跑 N 秒 → 写报告（位移 / 过点数 / 圈数 / 有无 NaN）；
  6. 产出一份「**数据层缺口清单**」：哪些字段在真引擎里语义不明或不够用。
* 交付：能开一圈的 demo 场景 + 缺口清单。
