# 38 · Pacejka 数据布局：32 × 144 字节（本轮定案）

> 本文回答 `docs/37` §5 留下的悬案：「谁读 `+0x140C`」。
> 答案：那个偏移附近就是**一组轮胎系数条目的装载循环**，它同时给出了
> **条目数**、**条目大小**、**源表位置**三个关键量。

## 1. ★★ 装载循环（`0x47af60`–`0x47af93`）

```asm
0x47af4e  lea  edi, [ebp + 0x140C]     ; ★ 目的：对象内的 int[] 索引表
0x47af52  mov  [esp+0x1c], edx
0x47af60  mov  eax, [esp+0x14]         ; 源对象
0x47af64  add  eax, 0x4880             ; ★★ 源表基址 = 源对象 + 0x4880
0x47af69  push 0x90                    ; ★★★ 144 = 36 floats（Pacejka 一个条目）
0x47af6e  push eax
0x47af6f  mov  eax, [esp+0x24]
0x47af73  push eax
0x47af74  call 0x666c10                ; ★ memcpy(dst, src, 144)
0x47af79  mov  ecx, [esp+0x28]
0x47af7d  add  esp, 0xc
0x47af80  mov  [edi], esi              ; ★ 把条目序号写进 +0x140C 表
0x47af82  inc  esi
0x47af83  add  ecx, 0x90               ; 步进 144
0x47af89  add  edi, 4                  ; 索引表每项 4 字节
0x47af8c  cmp  esi, 0x20               ; ★★★★ 32
0x47af93  jl   0x47af60
```

## 2. ★ 三方互证：条目数 = 32

| 判据 | 出处 | 值 |
|---|---|---|
| 本循环上界 | `cmp esi, 0x20` @ `0x47af8c` | **32** |
| `setPacejka` 的参数校验 | `docs/20` §1：`cmp eax,0x20 / jge <错误退出>`（轮胎槽位必须 `[0,32)`） | **32** |
| `MapTrack.mapper` | `docs/36` §1，数组实测 32 项（取值仅 {0,1,2}） | **32** |

⇒ 三条独立来源同一数字。

## 3. ★ 条目大小 = 144 字节 = 36 floats

`push 0x90` + `add ecx,0x90` 两处一致，且 `36 × 4 = 144` —— 与 `docs/20`
（`tyre[tyreIdx*36+idx] @ +0x20c`）、`docs/35`（`pacVarIdxs_v3` 最大索引 35）
**三方同值**。⇒ 所有 36 槽的规格被两次独立确认。

## 4. 对象/表之间的关係

★ **两套偏移属于两个不同的对象**（不要混）：

| 偏移 | 归属 | 含义 |
|---|---|---|
| `+0x20C` | 轮胎对象 | **36 个 f32 系数**（`docs/20` §1，写入端在 `0x4834e0`） |
| `+0x140C` | **本循环的目的对象** | **32 项 int[]**，装载/登记索引（`esi` 序号） |
| `+0x4880` | **源对象** | 144 字节 × 32 条的**主系数表**（拷贝源） |
| `+0x14DC…+0x14FC` | 本循环所在对象 | 紧随其后被写入的字段（向量/矩阵，见 §5） |
| `+0x3C44…+0x3C58` | 另一个大对象（`0x460fde` 处） | 六个 float 被清零（初始化） |

## 5. 装载循环之后紧接着的代码（下一步的入口）

`0x47af99` 起是**矩阵/向量运算**，形态为标准的 3×3 乘法：

```asm
0x47b04a  movss xmm4, [ecx+0x78]
0x47b07c  movss xmm3, [ecx+0x88]
0x47b084  mulss xmm3, xmm2
0x47b088  mulss xmm4, xmm1
0x47b08c  addss xmm3, xmm4
0x47b093  mulss xmm4, [ecx+0x68]
0x47b098  addss xmm3, xmm4         ; xmm3 = m00*v0 + m10*v1 + m20*v2
```

⇒ 该函数（起点候选 `0x47a957`，**无 `E8` 调用者**，与音频那处一样走间接调用）
= 「装载 32 条系数 + 立即做一轮坐标/受力变换」。**它很可能就是轮胎受力计算的入口** ✗
（未验证：需要继续往下追 `+0x140C` 表里的条目如何被当作索引用到系数上）。

## 6. Java 侧映射闭环（`docs/37` 补记）

### 6.1 具名字段 → 真槽号

`out_pseudo/java/classes/game/parts/PacVals.java`（121 行）里是 **20 个静态字段**：

```
pacVals_0, pacVals_1, … pacVals_19        ← 恰好 20 个
```

`PacejkaGlobals.pacVarIdxs_v3` 也恰好 **20 项**，且**使用 v3 的配方正是 3 个**
（`RH`/`RM`/`RS` 一类的竞赛胎）。⇒ 映射关系确定为：

```
pacVals_N  ≡  真槽号 pacVarIdxs_v3[N]
```

即 **`{2, 12, 0, 4, 13, 11, 14, 3, 17, 10, 1, 6, 7, 8, 18, 19, 15, 16, 34, 35}`**。
`pacVals_0` 就是槽 2（µ/地面抓地缩放），`pacVals_2` 就是槽 0（stiction）——
与 §2 的 setter 结论一致。

### 6.2 ★ 7 个「全局常量槽」

`PacejkaGlobals` 另有 `common_pacVarIdxs = {15, 16, 26, 24, 25, 22, 23}` 与
`common_pacVars = {1000, 6000, 10.0, 0.0, 0.0, 1.0, 1.0}` ⇒ 这 **7 个槽对**

| 真槽号 | 常量值 | 备注 |
|---|---|---|
| 15 | 1000 | 载荷量级（1000 ≈ N 或 kg） |
| 16 | 6000 | 载荷量级上限 |
| 22 | 1.0 | 中性乘子 |
| 23 | 1.0 | 中性乘子 |
| 24 | 0.0 | 零偏置 |
| 25 | 0.0 | 零偏置 |
| 26 | 10.0 | 某个上限/温标 |

★ 其中 **22–26 超出了那 20 项压缩表**（v3 最大只到 35，20 项压缩映射里不含 22–26 的位置）
⇒ 说明引擎对这 7 个槽有**独立于压缩表的全局写入路径** ✗（未定位；已如实记录）。

★ 未解释的冲突 —— ★ **已定案（见 `docs/39` §2.2）**：引擎内置的 36 槽默认模板
（静态地址 `0x742948`）在槽 15/16 处是 **3000.0 / 1000.0**，而 `common_pacVars` 是
**1000 / 6000** ⇒ 两者不一致 ⇒ **`common_pacVarIdxs` 是运行时"覆盖"**，
不是"模板本来就有的常量"。模板给默认值，随后 Java 侧用常量盖掉。
（槽 22–26 则逐位吻合：1.0 / 1.0 / 0.0 / 0.0 / 10.0 —— 这是两条独立判据的互证。）

## 7. 本轮新增锚点

| 地址 | 含义 |
|---|---|
| **`0x666c10`** | ★ memcpy 助手（`(dst, src, size)`），本循环与 `0x460fde` 处都用它 |
| `0x47af60` | 装载循环体（32 × 144 字节） |
| `0x47a957` | 含该循环的函数起点候选（前有 `push edi / leave` 收尾，紧接 `movss xmm0,[0x6ecd94]`） |
| `0x460fde` | 另一个读写 `+0x4880` 的对象（把 `+0x3C44…+0x3C58` 清 0） |

★ 工具（本轮新增，均可复用）：
- **`tools/find_disp.py <位移>`** —— capstone 验证「某位移被真正当作内存操作数」的位置。
  ★ 教训落地：裸字节扫描会被指令立即数骗（`0x20C` 的 6 个命中里 5 个是假的），
  必须用 capstone 校验「指令起始 + 恰好结束于位移之后」。
- **`tools/dis_at.py <地址> [前后字节] [--from]`** —— 精确起点反汇编；
  `--from` 用于已知起点直接后读（`at.py` 的启发式在 `0x47af4e` 上失败过）。
- **`tools/dis_linear.py <地址>`** —— 由 padding 边界找函数起点后线性解码。
