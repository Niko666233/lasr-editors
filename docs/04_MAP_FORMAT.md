# P3.4 —— 地图归档与场景目录（实测）

> 状态：**目录格式已确证**（多重重验证通过）。
> 场景实例数据（未打标签的子归档）尚未解，见文末「仍缺」。

## 1. 为什么会有 93 MB "未覆盖"

全量 RPAK 提取时，`maps/*.rpk` 出现 7–15 MB 的连续未覆盖区。
**这不是加密、不是压缩、也不是地形高度场** —— 它是一个**未打标签的场景目录**，
完全不含 `<4 字符 tag><u32 size>` 结构，所以链式 walk 在这里必然断掉。

`gap00` 总是从 **0x208** 开始 = 紧跟在 512 字节索引之后，
即**每个地图归档的第一个资源就是这张目录表**。

## 2. 目录记录格式（已确证）

```
偏移  类型      字段
 +0   u16       type         物体类别（见 §4）
 +2   u16       group        分组/生成批次
 +4   u32       A            类别内索引
 +8   u32       B            所属资源池 ID
 +10  f32       scale        实测恒为 1.0
 +14  u32       fileOffset   .rpk 内**绝对偏移**
 +18  u32       size         长度（**含 8 字节 tag 头**）
  ---  22 字节定长 ---
 +22  u8        nameLen      含结尾 NUL
 +23  char[]    name         物体名（NUL 结尾）
```

> 记录从 gap 偏移 **1** 开始（首字节是前一块的残留）。

### 判定依据（三重独立验证）

1. **61 条记录无缝走完**，中间一次都不断（自动拟合 start/fixed 得到唯一解）。
2. **size 链精确闭合到文件末尾**：
   `49,796,883 + 492 = 49,797,375` = `boulevard.rpk` 的**确切文件大小**。
   相邻记录满足 `offset(n+1) == offset(n) + size(n)`。
3. **16 条记录的 offset 直接命中真实 `<tag>` 条目**，且
   `size == 条目 size + 8`（例：`ccw_mirror` 记录 20,760 → `ISCX` 条目 20,752）。

## 6. 仍缺

* **未打标签的子归档**：`fileOffset` 落在 20,751,552 起的连续区（约 29 MB），
  那里是**场景实例数据**（物体变换矩阵、放置、赛道样条）。
  它没有 tag，必须靠内容特征定位；`gap_census` 显示该区 float 占比 68–70%。
* `group` / `A` / `B` 三个字段的精确语义（目前只能看出它们把记录分成资源池）。

### 93 MB 的构成（已分类）

93 MB 未覆盖区**不是一种东西**，至少分三类：

| 类别 | 位置 | 特征 | 状态 |
|---|---|---|---|
| **场景目录** | `maps/*/gap00` (0x208 起) | 22 字节记录 + 名字，size 链闭合到 EOF | ✅ **已解** |
| **顶点/几何流** | `maps/coastline/gap00_00020282.bin` (11 MB) | `0xffffffff` 哨兵 ×48,719，**间距 11 dwords（27,957 次）/ 13 dwords（17,724 次）**；`0x3f800000`(=1.0f) ×11,218；大量 ±2.0f | ⏳ 步长已知（44 / 52 字节），字段未定 |
| **位打包流** | `maps/hills/gap00_02007574.bin` (3.1 MB) | `0xaaaa0020` / `0x0010aaaa` / `0x49249249` 等**重复位模式**，float 占比 81.6% 但首 12 个 float 全 0 | ⏳ 疑似压缩/位打包（不是原始几何） |

其余各图 `gap01/02`（4–8 KB）都是**第二张小目录表**（同 §2 格式）。

> coastline 那条尤其值得注意：`0xffffffff` 的规则间距说明它是**定长结构数组**，
> 用与 INVO 相同的方法（哨兵间距直方图 → 步长；单位浮点三元组 → 法线偏移）
> 应该能直接解出，不需要反汇编。
