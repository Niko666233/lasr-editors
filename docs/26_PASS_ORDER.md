# 26 · 渲染通道顺序（动态实测，已取得）

> 由 `tools/d3d9_tracer.py` 实机采集：硬件执行断点挂在 `IDirect3DDevice9` 的
> vtable 槽位上，**每次命中读 `[esp]` = 调用者的返回地址** —— 即"谁发的这条调用"。
> 采集规模：**8095 条记录 / 1684 帧 / 3995 次渲染调用**（本机、窗口模式、设置档 0）。

## 1. 核心结论：调用被收敛到极少数函数

| D3D9 调用 | 次数 | 发起者（返回地址 → 函数） | 含义 |
|---|---|---|---|
| `Present` | **1676** | `0x500241` → **`0x5001f0+0x51`** | **帧循环 / 呈现函数**（1676 ≈ 帧数 1684 ⇒ 一帧一次 ✓） |
| `DrawIndexedPrimitive` | **1536** | `0x5331f7` → **`0x533180+0x77`** | **绘制分派器**（`0x533180`）—— 全部绘制出自它 ✓ |
| `BeginScene` | **766** | `0x505116` → **`0x5055a0+0x1e5`** | **场景/通道起始**（另 6 次来自 init 路径 `0x503520+0x1de`） |
| `Clear` | 3 | `0x5032c0+0x1d/0x58/0x93` | **只在初始化阶段**清屏 3 次（DX9 后端 init 内） |

> ⚠ 函数起点归属以 **§6 的修正版**为准：`0x533180` 是**无帧指针的 thiscall 序言**
> （`push esi; mov esi,ecx`），初版符号化器只认 `55 8B EC` 序言 ⇒ 曾把起点错报成 3 KB 之外的
> `0x5325d0` ✗。修正办法：函数起点集 = **所有 `E8` 调用目标** ∪ 序言特征（9,198 个）。

⇒ 与静态分析的"引擎自建渲染层"完全一致 ✓：外部只看得到**一个帧循环 + 一个网格提交函数 +
一个 BeginScene 点**，D3D 调用不是散落各处，而是**收敛成几个入口**（这也正是 ReShade
在 DX9 下失效的原因：它按常规方式挂设备 vtable，而游戏的调用形貌与常规 D3D9 应用不同）。

## 5. 附带发现的引擎结构

- **DX9 后端 init = `0x5026d0`**（唯一调用者 `0x6e53e5`，后者 `mov ecx,[0x781e80]`），
  初始化阶段清屏 3 次、`BeginScene` 6 次都出自它的函数体 ✓
- 引擎单例 `0x781e80`（853 处引用 ✓）与状态块 `0x781e00/04/0c/10` ✓
- **一帧** = `BeginScene`(0x505116) → 1536/1684 次 `DrawIndexedPrimitive`(0x5331f7) → `Present`(0x500241) ✓

## 6. ★ 完整调用图（静态反汇编追出，2026-09-28 补）

从"发绘制"往回追三层，**材质 pass 循环**被完整还原：

```
帧循环
  Present            ← 0x5001f0 (+0x51)          x1676
  BeginScene         ← 0x5055a0 (+0x1e5)         x766
  Clear x3           ← 0x5032c0（DX9 init 内）

批次刷新 0x533250  ←（每批一次）
  ├─ 若 [esi+0x794]（本批索引数）== 0 → 直接返回
  ├─ [esi+0x77c]（参数脏标志）非 0 → call 0x531df0(this, [esi+0x820])  冲刷参数缓存
  ├─ mov eax,[esi+0x774]            ★ 当前材质对象
  ├─ call 0x52ffc0(this, 材质, 0)   ★ 返回该材质的 pass 数 → ebx
  └─ for i in 0..ebx-1:
        call 0x530080(this, 材质, i)  ★★ 应用第 i 个 pass = 材质→D3D 状态绑定
        call 0x533180(this)           ★★ 发绘制
     call 0x5300e0(this, 材质)        还原/收尾
     然后 [esi+0x794]=0

绘制分派 0x533180（每批每个 pass 一次）
  ├─ mov ecx,[0x782cf4]; call 0x52fe80    绑定网格顶点流
  ├─ mov eax,[esi+0x778]; dec eax; cmp eax,3; jmp [eax*4+0x533240]   几何类型 1..4
  └─ 四个分支各发一条 D3D 绘制（[0x781e04] 取设备、[设备] 取 vtable）：
       分支 A → call [edi+0x144] 槽81 DrawPrimitive      图元 4=TRIANGLESTRIP, 计数 [esi+0x794]/3
       分支 B → call [edx+0x148] 槽82 DrawIndexedPrimitive 图元 4=TRIANGLESTRIP  ★ 实测 1536 次都走这里
       分支 C → call [ecx+0x144] 槽81 DrawPrimitive      图元 5=TRIANGLEFAN,  计数 [esi+0x794]-2
       分支 D → call [ecx+0x144] 槽81 DrawPrimitive      图元 1=LINELIST,     计数 [esi+0x794]

顶点流绑定 0x52fe80
  ├─ [esi+0x718] 个 8 字节记录 @ [esi+0x18]  → 逐条 call 0x52e800(this, 0, a, b)
  ├─ [esi+0x71c] 个 8 字节记录 @ [esi+0x618] → 逐条 call 0x52e800(this, 1, a, b)
  └─ jmp 0x52e110（收尾）
     另有：若 [esi+0x718]==0 且 [0x782078]==1 且 [0x782068]>0 → call 0x532070（单例 0x781e80）

单流绑定 0x52e800(this, 流号, a, b)
  ├─ 按流号选寄存器窗口：流0→[ecx+8] 且基数 +0x72；流1→[ecx+0x10] 且基数 +0x132
  ├─ mov eax,[esp+0x70]; dec eax; cmp eax,0x1c; ja ...; jmp [eax*4+0x52f990]
  │     ★★ 28 路跳转表（0x1c+1 = 29 个语义分支）= 顶点元素语义解析
  └─ 分支内引用全局名串 0x781f90 / 0x782014 / 0x781f38 并 call 0x5f9190（导入桩）
```

**结论**：
1. **pass 循环是"每材质 N 个 pass"结构** ✓ —— `0x52ffc0` 问 pass 数、`0x530080` 应用第 i 个 pass、
   `0x5300e0` 还原 ⇒ 与 docs/23 的"材质 = 变换 × 图层 × 光照 三段组合 + `#define` 变体轴"
   完全吻合：**变体轴就是这里的 pass 序列** ✓✓
2. **`0x530080` 是"材质规格 → D3D 状态"的唯一绑定点** ✓✓（docs/23 的公式、9 个 `.fx` 变体、
   8 种混合、4 种阴影最终都反映在它设的状态里）⇒ **下一步就是读它**。
3. 绘制按几何类型（三角带/三角扇/线段）分四路 ✓；实测 1536 次全走索引分支 ✓。
4. 顶点声明走 **28 路语义表** ✓（对应 29 个 D3DDECLUSAGE 风格分支）✓。

### 8.1 每帧的通道时序（逐帧实测，指针为本次运行的实际值）

```
① 主场景 RT 复位     SetRenderTarget(dev, 0, 0x9a071e0) + SetDepthStencilSurface(dev, 0x99d4ec0)
                     ← 0x504710+0xc5 / 0x504710+0xda
② 离屏通道           SetRenderTarget(dev, 0, 0xd5bfe80) + SetDepthStencilSurface(dev, 0xd78b940)
```

### 8.5 ★ 调用者函数起点的自我纠错（`owner_start.py`）

初版符号化器只靠"E8 目标 ∪ 序言"，会产出**假起点**：`0x504a2a` 被当成函数起点
（恰好等于那个返回地址），于是在日志里显示成 `0x504a2a+0x0`，看起来像个"没有任何调用者的函数" ✗。

**假起点的判据（决定性）**：一个真函数起点**不可能既没有 E8 调用者、也没有 4 字节数据指针引用** ✓。
用 int3 填充边界反推真起点后：

| 地址 | 真起点 | E8 调用者数 | 判定 |
|---|---|---|---|
| `0x504a71`（离屏 SetRenderTarget） | **`0x504a20`** | **3**（`0x4c0d44` / `0x4c19e9` / `0x509ebc`） | ✓ 真 |
| `0x504b09`（同函数的 SetDepthStencilSurface） | `0x504a20`（同上） | 3 | ✓ 真 |
| `0x4ffad0`（Clear 发起者） | `0x4ffad0` ✓ | **8** | ✓ 真 |
| `0x531f00`（DX8 主绘制入口） | `0x531f00` ✓ | **6** | ✓ 真 |

⇒ §8.1 里"离屏通道 ← `0x504a2a`"应记作 **`0x504a20`（函数起点，`+0x51` 处发 SetRenderTarget）** ✓；
三个调用者（`0x4c0d44`/`0x4c19e9`/`0x509ebc`）**全部落在 `0x4c0xxx`–`0x4dxxxx` 渲染器模块区** ✓✓
⇒ 下一步读这三个调用者即可判定离屏通道身份（阴影图 / 镜像）✓。

工具：**`tools/owner_start.py`**（给定返回地址 → int3 边界反推真起点 + 调用者/数据指针验证）✓
