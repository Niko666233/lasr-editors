## 1. 先纠一个此前的误判：「hills 3.1 MB 位打包流」

`maps/hills/gap00_02007574.bin`（3,105,086 B）此前记为「疑似压缩/位打包，非原始几何」。**错。**

它落在场景目录里 `type=99`（纹理）资源 **`track_other_comb.png`** 的字节区间内
（`off=0x01DA962A`，`size=5,587,080`）：gap 起点相对纹理起点 **+2,481,994**，
且 **`gap == rpk[纹理区间][2,481,994:]` 逐字节相等、末尾精确对齐**。

→ 它就是那张 **5.59 MB DXT5 纹理的后 55.6%**，而"16 字节记录 + `aa aa aa aa` / `55 55 55 ff` 位模式"
＝**BC3 压缩块**（前 8 字节 alpha 端点+索引，后 8 字节 BC1 颜色，颜色端点为 RGB565
如 `0xAAAA` / `0x0020`）。是**提取器把贴图尾部误判成 gap**，不是新格式。

> 教训：文件名为 `gap<nn>_<起始偏移>` 的产物**不保证是独立资源**；
> 归因前先用场景目录的 `(fileOffset, size)` **查它落在谁的区间里**。

## 2. 顶点记录（与 P3.5 一致，此处独立复核）

```
<f32 u><f32 v><f32 c1><f32 c2><f32 x,y,z><f32 nx,ny,nz><u32 color>
  0        4        8        12      16..24       28..36        40       = 44 B
```

52 字节 = 13 dwords，即上述 11 项再**追加 2 个 f32**（第二套 UV / 切向）。

⚠️ **记录里没有「哨兵」**：`+40` 那个恒为 `0xffffffff` 的 dword 是**白色顶点色**。
我第一遍把它当记录分隔符，于是整体字段偏移错了一位 ——
与 `docs/05_COASTLINE.md` 里记下的**同一处坑完全一样**。
判据是：**只有把 `nrm` 放在最后 3 个 f32 上**，模长才 = 1.000，
于是 `+40` 只能是别的东西（颜色）。

实测（`maps/coastline` 的 44 字节记录）：

| 字段 | 观测 | 判定 |
|---|---|---|
| u, v | 0.5 / 0.625 / 0.875 / 1.0，v ∈ {0,1} | **主 UV** |
| c1, c2 | 0.2291 / 0.7138（同一块内恒定） | 光照贴图 UV 或材质参数（P3.5 待定项） |
| x, y, z | X∈[−6088, 9926] Y∈[10, 1162] Z∈[−8031, 2433] | **世界坐标（米），Y 为上** |
| nx, ny, nz | **模长 = 1.0000**（99.8% 在 ±2% 内） | **法线** |
| color | 恒 `0xffffffff` | **白色顶点色** |

法线单位长这条判据把字段划分钉死了：换任何一个 3 连 f32 的切法都凑不出 99.8% 的单位长。
（与 P3.5 的 48,428/48,719 = 99.4% 同一量级，覆盖不同切片。）

## 3. 网格块头（44 字节，紧跟其后才是顶点数组）

```
<u32 1> <u32 fmt> <u32 vertCount> <u32 triCount> <u32 idx> <f32 ×6>
   1      9/8/5/13…     726            340           1729    (种子位置 + 种子法线)
```

**严格交叉验证**（coastline @106,920）：头部 `vertCount = 726`，实际连续记录数 **726**，
块长 **31,944 = 726 × 44** 精确成立。

- **顶点数上限 ~1023**：594 个块里最大的都是 1010–1023 → 索引位宽 **10 bit**（≤1023），
  一超就切块。这是**独立于任何头的**格式推断，正好解释为何块都很小。
- `fmt` 取值 5–18（可能 = 顶点格式/步长编号）；`idx` 语义未定（`idx/triCount` 均值 6.9，
  不是三角带索引数，更像字节长度或顶点索引总量）——**两个待定字段，不影响顶点本体可用性**。

## 4. 场景实例记录（ASCII，两种）：

```
gametype 0x00030050\r\n
params 451.433,98.835,-263.730,1.722,0.000,0.000\r\n
```

- `params` = **位置 x,y,z（米）+ 旋转 rx,ry,rz（弧度）**。
  证据：最常见旋转值 `0.0`(1549) / `±1.571`(230) = **±π/2**，
  全量 **62.5%** 的旋转分量量化到 π/2 倍数（其余为任意水平朝向，合理）。
- 与 `docs/07_GAMETYPE_MAP.md` 的 **RSD 块是同一套记录格式** ——
  区别只是这里没有 RSD 外层包裹。
